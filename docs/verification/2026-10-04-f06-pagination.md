## Подтверждено кодом

- `packages/contracts/src/rewards.ts`: cursor `actor|scope|purpose|id`, UUID и три допустимых назначения, scope=all только для личной истории, строгая структура/лимит длины. Старый date|id отклоняется. Курсор не является подписью или полномочием; прежние серверные ограничения доступа уже существовали, чтение чужих данных прежним курсором не установлено.
- `packages/domain/src/rewards/read.ts`, `decisions.ts`, `shared.ts`: сохранённый доступный anchor определяет `(created_at,id)` в SQL. Личная история проверяет владельца; рабочая очередь — актуальную сессию, отдельное точное полномочие, область, purpose, чужого получателя и ожидаемый статус. Cursor сохраняет область даже при изменении порядка областей. Ушедшая из очереди заявка даёт page_changed; личная история продолжает её использовать. Это живой список, без гарантии снимка всех страниц.
- Миграция `000017` задаёт `redemptions.created_at` как timestamptz(3). Первоначальная гипотеза о потере микросекунд на текущей схеме не подтвердилась. Тест равных timestamp проверяет UUID-порядок; заявлений о воспроизведённом пропуске из-за округления нет.
- `apps/app/src/shared/server/rewards.ts`: 400 INVALID_CURSOR для неподходящего anchor и 409 PAGE_CHANGED для вышедшей из очереди записи; schema-invalid/old/extra/duplicate queries дают 400 BAD_REQUEST. Ответы no-store. Route Handlers сохраняют Node.js и остаются адаптерами. API/UI требуют совместного выпуска; перезагрузка страницы заменяет старые курсоры.
- `reward-catalog.tsx`, `reward-decisions.tsx`: существующие alerts объясняют восстановление через прежнее обновление. Обновление оставляет первую подтверждённую страницу и pageParam=null, обрезает остальные страницы и перечитывает начало. Сетевая ошибка оставляет первую страницу с подписью; решения/выдачи/отмена и дальнейшее paging блокируются до обновления. 404 скрывает прежние рабочие строки. Формы/причины/неопределённые мутации сохраняют прежние guards.
- `tests/integration/reward-pagination.test.ts`: реальные операции reserve/approve/fulfill, cursor actor/scope/purpose/anchor, точные права и отзыв сессии, равные timestamp и независимый UUID-порядок, сохранение области, переходы anchor в обеих очередях, HTTP ошибки и no-store. Runtime — impuls_app; fixture owner изменяет время только своих записей, отключает/включает trigger в одной транзакции с flush deferred constraints. Cleanup удаляет только fixture IDs. Первый reader до/после имеет одинаковые balance/ledger/audit/outbox/quota.
- Нет новых миграций, пакетов, конфигурации экономики или внешних операций. UUID-курсор каталога и остальные readers не изменяются. `SYNTHETIC_REWARDS_ENABLED` по умолчанию false. Обновлены план, продукт, дизайн, README, next-steps и три surface briefs.
