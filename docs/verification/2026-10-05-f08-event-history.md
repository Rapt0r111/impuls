## Подтверждено кодом

- `packages/contracts/src/notification-status.ts`: обязательная область, limit 1–50, cursor actor/scope/purpose/event, strict projection событий и ответа. Предыдущая сводка/recent20 сохраняет контракт.
- `packages/domain/src/notifications/events.ts`: один SQL snapshot для active actor/session, exact admin.notifications, источников разрешённой области, anchor и страницы. Native PostgreSQL created_at/id определяют порядок и границу без округления к wire-дате. Статусы перечитываются; источник должен оставаться synthetic/pending. Скрытая область проверяется до anchor. Изменений записей нет; служебный event UUID передаётся только в курсоре, не строках.
- `apps/app/src/app/api/v1/admin/notifications/events/route.ts`: authenticated Node GET, строгие query/duplicates, прежний flag default false, private/no-store, 400/401/403/404/503 без сырых ошибок; POST 405 средствами Next.js.
- `apps/app/src/features/notifications/notification-events.tsx` и `notification-status.tsx`: выбранное пользователем закрытое native disclosure «Все события», lazy query, самостоятельные timestamp/refresh/next, Back до выхода из раздела. 503/offline сохраняет подтверждённую текущую страницу; 400 скрывает изменённую страницу. 401/403/404 отменяют параллельные queries и очищают сводку/страницы, включая отказ родителя. Scope key, AbortSignal и проверка response scope защищают от поздней подмены. Общие labels/date/error вынесены в notification-format.ts без изменения прежних подписей.
- `notification-status.css`: только локальное правило 14px для длинного пояснения нового disclosure согласно §7; токены/шрифты/motion не меняются. Схема 000001–000022, grants, runtime, dependencies и bun.lock этим срезом не менялись. Нет реальных сообщений, новых цен/прав или P-решений.
