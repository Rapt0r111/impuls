## Подтверждено кодом

- `db/migrations/000022_notification_status_reader.js`: отдельное `admin.notifications`, без выдачи bindings; приложение читает только outbox_id/status/error_code private receipts. SELECT lease/token и любые записи запрещены, worker ACL сохранены. Down при назначенном праве отклоняется атомарно; без bindings сохраняет историю.
- `packages/domain/src/notifications/status.ts`: полномочие, действующая сессия и counts проверяются одним SQL statement. Сохранённый источник assignment/review/correction/redemption задаёт точную область; текущее членство получателя не заменяет источник. Соседние области и непригодные исходные события исключены. Семь complete counts и пять фиксированных причин не содержат получателей, текстов, source IDs или lease. Reader ничего не claim/process и не пишет.
- `apps/app/src/app/api/v1/admin/notifications/route.ts`, `packages/contracts/src/notification-status.ts`: строгий GET, только необязательный UUID scope, private/no-store, проверка сессии и отдельный выключенный по умолчанию `SYNTHETIC_NOTIFICATION_STATUS_ENABLED`. POST не поддержан. Нейтральный 503 не раскрывает исключение.
- `apps/app/src/features/notifications/notification-status.tsx`: ручное обновление и явная симуляция без Telegram-отправки. Offline/503/невалидный успешный ответ сохраняют датированную подтверждённую сводку. 401/403/404 очищают все её query keys, включая повторное открытие; статус действует и при не-JSON теле ошибки. Нет polling, transport actions или localStorage. Навигация следует серверному discoverability и прежнему Back/leave guard.
- План, PRODUCT, DESIGN, README, ADR index, next-steps и surface brief согласованы с этим расширением. Runtime/пакеты/lockfile не менялись этим срезом; их прежние накопленные изменения сохранены. Remote migration, выдача реальных прав и deployment не выполнялись.

## Исправленные сбои во время проверки

- Первый typecheck выявил недискриминированный union результата reader; варианты разделены, повтор прошёл.
- Первые integration runs: 5 failed/4 passed/2 skipped. Fixture создавала сессии до bindings, а существующий trigger отзывал их. Сессии теперь создаются после прав; проверки срока полномочий явно изолируют ожидаемый session state. Отзыв через HTTP проверяет настоящий 403.
- Два runner failures: внешний Telegram SDK задерживал реальный browser-to-DB, затем select не имел ожидаемого имени. SDK замокан только в тесте, select получил явный aria-labelledby.
- Следующие browser failures выявили неоднозначные locators для двух dl/Next announcer и mock fulfillment, обходивший offline context. Locators ограничены секцией, offline fetch действительно abort. После исправлений 16 scenarios прошли; затем добавлены три проверки не-JSON 401/403/404, финально 19 прошли. Временные diagnostic probes удалены.
- После первого просмотра снимков увеличен отступ пояснения возле focused disclosure. Последние 11 сохранённых снимков проверены независимо; других визуальных исправлений не потребовалось.
