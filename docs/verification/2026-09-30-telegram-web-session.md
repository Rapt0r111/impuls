## Подтверждено кодом и журналом

Пользователь подтвердил среду Telegram Web в браузере. Вход и выход использовали `SameSite=Lax`; после успешного входа UI читает `/api/v1/me/permissions` и показывает отказ сессии при 401. ADR-0002 заменяет политику на `HttpOnly; Secure; SameSite=None; Path=/; Partitioned`, без `Domain`. HTTP-тест проверяет signed synthetic initData → реальную БД → ответ с cookie → `/me` 200; неверный Origin и CSRF на выходе дают 403, корректный выход — 204 с удалением partitioned cookie, отозванная сессия — 403, отсутствие cookie — 401. Неверная и устаревшая подпись дают 401 без cookie; тело успешного ответа не содержит sessionToken. Изолированный сервер тестового среза получает только синтетический bot token; Production environment не меняется.

HTTPS-браузерный стенд использует рабочий UI, локальный сертификат и синтетические API. Сайты `.test` разрешаются только на loopback. Он настраивает `Network.setCookieControls` через CDP и проверяет реальную отправку cookie; это не тест физических устройств или всех настроек блокировки cookie. Сертификат создаётся OpenSSL (на Windows — установленный Git OpenSSL, на Linux — `openssl`, переопределение через `TEST_OPENSSL`), временные PEM удаляются после прогона.

## Промежуточные сбои

Первый unit-прогон ожидал `SameSite=None`, тогда как Next.js сериализует `SameSite=none`. HTTP-атрибут нечувствителен к регистру; исправлено ожидание, поведение сервера не менялось. Предварительный стенд с перехватом запросов и dev-сборкой получил тайм-ауты и не доказал поведение cookie; заменён реальным локальным HTTPS и production-сборкой. Контроль непартиционированного None не подтвердил полную блокировку сторонних cookie и не включён в итоговые утверждения. Первый запуск PostgreSQL в sandbox не создал restricted token; разрешённый повтор с повышением прав запустил изолированный кластер. Эти сбои не выдаются за прошедшие проверки.
