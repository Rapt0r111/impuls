## Подтверждено кодом

- `db/migrations/000008_task_returns.js`: неизменяемое решение `return`, обязательная причина 1–2000 символов, единственное решение на отчёт. RLS включён; `impuls_app` получает только SELECT/INSERT; PUBLIC не получает доступ. Приёмка потребует отдельного расширения схемы вместе с F04.
- `packages/contracts/src/reviews.ts`: `GET /api/v1/reviews` с UUID-курсором, лимитом 1–50 (по умолчанию 20); очередь содержит критерии, текст, псевдоним, область, номер попытки, фонд и версии. `POST /api/v1/submissions/:id/review` принимает только `action: return`, `expectedVersion` задачи, причину и UUID `Idempotency-Key` в заголовке. Поля корректировки фонда и `accept` отклоняются.
- `packages/domain/src/tasks/reviews.ts`: точное право `task.review` без наследования области; собственные отчёты исключены из очереди и запрещены для решения. Транзакция блокирует допуск, право, сессию, задачу и ключ; порядок право → сессия согласован с триггером отзыва. После ожидания блокировок срок права/сессии проверяется по `clock_timestamp()`. Решение, статус/версия задачи и сохранённый ответ либо фиксируются вместе, либо откатываются. Повтор того же тела возвращает прежний ответ после проверки текущего доступа; другое тело/цель — конфликт. Рассматривается только последняя попытка в `in_review`.
- Новые Route Handlers проверяют сессию, Origin/CSRF, тело не более 32 768 байт и контракт; персональные ответы `private, no-store`. Чужая область и неизвестный отчёт дают одинаковый 404; отсутствие права очереди — 403. SQL остаётся в домене.
- Рабочие разделы «Мои задачи»/«Проверка отчётов» показываются по серверным полномочиям. Открывается одна форма. Причина сохраняется в памяти при ошибке/конфликте; неизвестный результат повторяет прежний ключ и тело. Несохранённый текст защищён при закрытии, переключении и выходе. Изменение допуска закрывает рабочие данные; отказ только в review не выдаёт недоступных действий. Выбор отчёта переносит фокус и прокручивает к его заголовку даже после длинной очереди.
- `tasks/read.ts`, `task-report.tsx`: последняя причина возврата видна исполнителю; начать доработку и повторно сдать можно через существующие транзакции. Старый отчёт и решение сохраняются. XP/баллы и фонд возврат не меняет.

## Проверенные сценарии

Точная область, соседняя область, собственный результат, отсутствующее/будущее/истёкшее/отозванное право; курсор; причина в деталях исполнителя; повтор прежнего запроса и конфликт тела; два параллельных повтора и два проверяющих; старая попытка после повторной сдачи; откат на неверной причине/версии; сохранность фондов и ACL/RLS. Отдельная гонка держит право SQL-блокировкой, наблюдает ожидание в PostgreSQL и отзывает право до продолжения операции. Отдельная проверка истечения сессии во время ожидания задачи не допускает решения и не оставляет ключ.

Реальный HTTP проверяет очередь, контракт возврата, Origin, CSRF, replay, 400/401/409 и no-store. Browser-to-database сценарий проходит отсутствие сети, повтор возврата, просмотр причины другим участником, начало доработки, повторную сдачу и новую попытку в очереди. Все `/api/v1` запросы этого сценария настоящие.

Синтетические browser сценарии проверяют 320/360/390/1280 px, пустую очередь, 503, потерю ответа, конфликт, запрет собственного решения, 401/отзыв доступа, сохранение текста и guard при переключении. Ещё четыре сценария открывают первый отчёт из 20 записей мышью/клавиатурой на 320/390 px и проверяют фокус/границы заголовка. Результаты визуального ревью — `2026-09-30-f03-return-ui-review.md`. Внешние UI-компоненты, изображения и зависимости не добавлялись; переиспользована система проекта.

## Выпуск и непроверенное

`000008` и новый сервер **не применены к Supabase/Vercel** в этой задаче. Перед развёртыванием нужен прогон PostgreSQL 17.6 CI, миграция тестового Supabase с проверкой ACL/Data API и deployed API. Миграция должна предшествовать развёртыванию: чтение собственных задач теперь обращается к `reviews`. Откат приложения на предыдущую версию может оставить таблицу с историей; `down` удаляет решения и не является процедурой сохранного отката.

Не проверены Telegram Android/iOS, клавиатура, крупный системный текст, safe areas, полный recovery/backup, нагрузка, outbox и отдельный лимит мутирующих операций. Следующий технический срез — приёмка одновременно с атомарным журналом/балансами F04, аудитом и отрицательными/конкурентными проверками. Реальные участники, правила экономики, служебные поощрения и пилот требуют P-решений.
