## Подтверждено кодом

- `packages/contracts/src/leaderboard.ts`: строгие query/response-схемы, реальный календарный месяц, UUID, limit 1–50, revision-курсор области/месяца.
- `packages/domain/src/ranking/read.ts`: read-only repeatable-read транзакция под runtime, новая проверка допуска/сессии, доступ только по действующему явно синтетическому членству точной области. Сумма XP журнала выбранного scope/month/Europe/Moscow со знаком компенсаций; баллы и остальные области/зоны не включаются. `rank()` даёт 1/2/2/4, UUID стабилизирует показ. Нет публичных нулевых результатов. Курсор меняющейся ревизии — `changed`, без смеси расчётов.
- `apps/app/src/app/api/v1/leaderboard/route.ts`: тонкий GET-адаптер, strict params/duplicate rejection, 401/403/404/409/503, private/no-store. `SYNTHETIC_RANKING_ENABLED=false` по умолчанию в `.env.example`. Выключение проверено доменным тестом; выключенный HTTP-ответ проверен по коду и отдельно браузерным синтетическим ответом, не внешним сервером.
- `apps/app/src/features/ranking/leaderboard.tsx`, `leaderboard.css` и `features/tasks/task-list.tsx`: раздел «Рейтинг», выбор области/месяца, личный результат, семантическая таблица, обновление/пагинация, защита несданного отчёта в существующем workspace. Native fields 16 px/44 px, клавиатурный focus, перенос длинных псевдонимов. `networkMode: always` даёт явный offline-отказ вместо скрытой паузы запроса.
- Схема, гранты, `bun.lock`, зависимости и runtime не изменены. Достаточна существующая локальная схема `000001–000014`. Новых реальных сведений, публикации, Git push/коммита, Supabase/Vercel операций записи или внешнего выпуска нет.

## Независимые результаты и UI

Тесты используют ожидаемые значения, не вычисленные алгоритмом приложения: 100/60/60/20 XP → места1/2/2/4; после реальной компенсации100 XP → 60/60/20 и места1/1/3, собственные0/null; отдельные900 XP октября сохраняются. Исключены500 баллов на каждую приёмку,700 XP соседней области,800 XP другой зоны и1000 XP неактивного участника. Месячная граница20:59:59.999Z/21:00:00Z и декабрьский переход проверяются существующим `ledger/economy.test.ts`. Исходный месяц для compensation-fixture задаёт владелец изолированной БД до операции runtime; production-журнал не меняется.

Проверены точное членство и отсутствие наследования task/admin-полномочий, срок/отзыв членства, неактивный пользователь, неправильная/отозванная/истёкшая сессия, disabled mode, пустой месяц, личный ноль, равные места на границе страницы, привязка cursor к scope/month/revision и неизвестный anchor. Настоящий HTTP валидирует параметры/дубли, no-store,401,404. Настоящий Chromium получает данные через API→PostgreSQL и показывает100 XP после выбора сентября; его ответы рейтинга не подменены.

Browser state matrix использует отдельно подписанные как синтетические API-фикстуры:320/360/390/1280 px,20→24 строк, клавиатурное обновление/focus, длинный неразрывный псевдоним, выбор области/месяца, empty/no-scope/disabled/loading/503,409 с сохранённым расчётом, stale, offline,401/403 со скрытием защищённой таблицы. Ошибок pageerror и горизонтального overflow нет. Физический Telegram и screen reader этим не проверены.

## Неизвестное и следующий срез

F05 требует ещё порогов уровней из версии правил/профиля и уникальной выдачи «Первый результат». Закрытие сезона, immutable snapshots и errata требуют отдельного контракта; текущий расчёт прошлых месяцев не объявляется опубликованным архивом. P-01…P-06, особенно реальная видимость P-05, остаются открытыми. Не выполнены внешнее развёртывание, PostgreSQL17 CI, physical Telegram Android/iOS, screen-reader проход, нагрузка/порог большой области и эксплуатационные критерии §12. Полная агрегация соответствует целевому малому составу, но её производительность не объявляется измеренной. F05/R1 не объявлены завершёнными.

Первичные технические источники: [PostgreSQL17 window functions](https://www.postgresql.org/docs/17/functions-window.html) для competition rank и [Supabase API security](https://supabase.com/docs/guides/api/securing-your-api) для разделения grants/RLS и private schema. Визуальный компонент следует существующей дизайн-системе; внешние визуальные источники и новые зависимости не использованы.
