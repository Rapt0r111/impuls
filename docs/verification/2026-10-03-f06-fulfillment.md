# F06: локальная выдача синтетической косметики

Дата: 03.10.2026. Требования: IMPLEMENTATION_PLAN.md §§ 5–7, F02/F06/F07 § 11, § 12; [контракт среза](../implementation/2026-10-03-f06-fulfillment-slice.md) и [ADR-0010](../adr/0010-synthetic-cosmetic-fulfillment.md). F06/R1 не объявляются завершёнными.

## Подтверждено файлами и кодом

- `db/migrations/000019_reward_fulfillment.js` расширяет только approved → fulfilled и сохраняет решение/условия. Уникальные immutable entitlements связаны с получателем, предметом, точной областью и заявкой; отложенный constraint trigger запрещает переход без соответствующего владения. Старые approved остаются approved. Runtime может SELECT/INSERT владение, но не UPDATE/DELETE; RLS включён, PUBLIC/Data API роли не получают таблицу или функции. Миграция не создаёт полномочия, цены, квоты или выдачи и не удаляет историю при down.
- `packages/domain/src/rewards/fulfillment.ts` проверяет отдельное точное reward.fulfill, активную сессию/получателя и запрет собственной выдачи. Replay требует актуального доступа; проверки повторены после row lock waits, включая recipient lock. Порядок quota → balance → redemption общий с резервом/решениями. Entitlement, переход, audit, нейтральный outbox и сохранённый ответ выполняются в одной транзакции; балансы, их версии, квота и финансовый журнал не меняются.
- `packages/contracts/src/rewards.ts` и `apps/app/src/shared/server/rewards.ts`: POST `/api/v1/redemptions/:id/fulfill` принимает только expectedVersion/reason, GET `/api/v1/redemptions/fulfillment` возвращает чужие approved разрешённой области. Общие Origin/session/CSRF/bounded JSON/idempotency/mutation limit/no-store предшествуют записи. Клиент не задаёт получателя, автора, статус, цену или entitlement. Route Handlers — адаптеры без SQL.
- `read.ts`, `write.ts`, `shared.ts`: личная история содержит основание, автора/время выдачи и ID владения; каталог возвращает owned. Сервер и уникальный индекс блокируют новую покупку того же предмета в той же области после fulfilled, включая смену цены/квоты.
- `reward-decisions.tsx` расширяет существующую очередь/встроенную форму параметром purpose. Показаны согласование, исходные условия/цена и отсутствие повторного списания; обязательны основание и новое подтверждение. Unknown/503/429/lost response сохраняют прежние body/key для manual replay, конфликт сохраняет текст и требует повторного открытия. `reward-catalog.tsx` показывает «Уже в коллекции» и личное свидетельство выдачи. Отдельные права управляют двумя действиями каталога; между ними сохранён 12 px gap. Не добавлены зависимости, токены, шрифты или motion.

## Исправления по проверкам

- Первая expiry fixture не учла существующий DB trigger: изменение valid_until отзывает сессию. Fixture восстанавливает только свою тестовую сессию после настройки срока, чтобы независимо проверить право; отдельные revoke-тесты остаются. Затем добавлено наблюдение реального Lock wait, чтобы тест не проходил лишь по первоначально истёкшему праву.
- Первый browser assertion обнаружил, что implicit label включал текст textarea после ввода. Поле получило стабильное aria-labelledby; повтор и disabled/reason assertions теперь проходят. Тестовые alerts ограничены рабочей секцией из-за Next.js route announcer. Ошибочный тестовый селектор кнопки повторного входа заменён фактическим заголовком revoked/session состояния. Эти промежуточные прогоны завершались с exit 1; финальные прогоны выше успешны.
- Copy выдачи отделено от copy решения: «Повторить ту же выдачу», «Сохраняем выдачу», «Ещё заявки на выдачу». Добавлена группа действий каталога с 12 px gap для обоих прав и browser assertions на 320/1280.
