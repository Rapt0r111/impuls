# Проверка: одна область без выбора и простые «Настройки начислений», 13.10.2026

Запрос владельца 13.10.2026: объяснить «Область» и убрать её, если она не нужна; «Настройки начислений» слишком сложные и непонятные.

Работа построена поверх PR #13 (`claude/pilot-polish-0nul95`). Сервер, схема, API и права не менялись. Среда: локальный PostgreSQL 16, `next start`, Chromium (Playwright) 320/360/390 px, синтетические данные. Telegram WebView, Android, iOS и Production не проверялись.

## Область

**Подтверждено кодом.** Область (`impuls.access_scopes`) — граница прав: каждое право (`role_bindings`), членство (`task_scope_members`), задача, поощрение и запись журнала относятся к точной области (§ 5 `IMPLEMENTATION_PLAN.md`). Удалить сущность нельзя без переделки всей серверной авторизации.

**Проверено запросом на чтение к Production 13.10.2026.** Область одна — «Пилот», в ней 3 участника.

**Изменено.** Название и выбор области показываются, только когда у человека больше одной области:

| Экран                                     | Было                                | Стало                                             |
| ----------------------------------------- | ----------------------------------- | ------------------------------------------------- |
| Постановка задач, форма                   | Обязательный список «Область»       | Нет поля; задача создаётся в единственной области |
| Постановка задач, строка задачи           | «Пилот · Обычный · до …»            | «Обычный · до …»                                  |
| Постановка задач, назначение              | «Активный участник области «Пилот»» | «Кому назначить»                                  |
| Карточка задачи, свободные задачи         | Строка/метка «Область: Пилот»       | Нет строки                                        |
| Очередь проверки                          | «Имя · Пилот», строка «Область»     | «Имя»                                             |
| Рейтинг                                   | Подпись «Пилот» под месяцем         | Нет подписи                                       |
| Управление каталогом, журнал, уведомления | Список «Область» из одного пункта   | Нет списка                                        |
| Ещё → Мои права                           | «Группа · Пилот» под каждым правом  | Только название права                             |

Признак «больше одной области» для экранов без собственного списка берётся из `/api/v1/me/permissions` (`useManyScopes`, `features/auth/session-context.tsx`). Экраны со своим списком областей (каталог, журнал, уведомления, рейтинг, доступ, поощрения) решают по нему. Если появится вторая область, поля вернутся сами.

Решение владельца 13.10.2026 («Убери пока область, у нас маленькая организация и один командир»): слово «область» убрано и из текстов интерфейса — подсказок, пустых состояний и ошибок («Все задачи», «Участники», «Задача больше недоступна» и т. п.). Сущность и проверка прав на сервере остаются.

## Каталог поощрений

Запрос владельца 2026-10-13: «Сделай более понятный Каталог. Сделай проще создание и покупки, больше визуала и меньше шума лишнего». Только интерфейс: API, миграции и серверные проверки не менялись.

**Изменено:**

- `features/rewards/reward-visual.tsx` (новый) — значок поощрения без загрузки файлов: эмодзи по смыслу названия (рамка, корона, кубок, знак, фон…, иначе 🎁) и свой цвет, стабильный для названия.
- `features/rewards/reward-catalog.tsx`, `rewards.css` — у участника: «У вас N баллов» (и «Ещё N в заявках») вместо двух строк баланса; карточки-плитки со значком, ценой, «Осталось N · до даты» и полосой «Не хватает N баллов»; кнопка «Получить». Подтверждение без галочки: значок, «Получить поощрение?», «−N баллов», «После заявки останется N баллов», одна кнопка «Получить за N баллов». «Мои заявки» — короткие строки со статусом-меткой («Ждёт решения», «Одобрено, ждёт выдачи», «Получено», «Отказано / Срок истёк / Отменено, баллы вернулись»), сроком ответа и причиной. Убраны служебные строки («Косметика выдана, право владения сохранено», «Возврат по истечении срока требует серверной обработки…», автор и основание выдачи).
- `features/catalog-admin/catalog-admin.tsx`, `catalog-admin.css` — у командира каждая позиция сначала показывает значок, название, цену, состояние («Доступно участникам», «Выключено», «Закончились») и строку мест «Выдано · ждут решения · свободно X из Y»; условия, история, график, квоты и изменение свёрнуты в «Подробнее и изменить».
- `features/catalog-admin/reward-quick-create.tsx` — перед кнопкой создания видно, как поощрение будет выглядеть у участников.

Подтверждение без галочки не снижает защиту: сервер по-прежнему проверяет версию, баланс, квоту и ключ идемпотентности; кнопка «Назад» закрывает форму без запроса.

**Проверено:** `bun run format:check`, `bun run lint`, `bun run typecheck`, `bun run build:app`; браузерные сценарии каталога и поощрений (320/360/390 px) и интеграционные тесты каталога и заявок с PostgreSQL — результаты в описании PR #14.
