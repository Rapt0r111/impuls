1. **Одобрение и выдача.** `reward.decide` одобряет через UI: `approved`, `decision_actor_id` = решающий, баланс 90/0 (резерв списан). Отдельный `reward.fulfill` выдаёт: `fulfilled`, `fulfillment_actor_id` = выдающий, ровно одна запись `entitlements`, баланс не изменился.
2. **Гонка двух уполномоченных.** Оба одновременно одобряют одну заявку: один видит «Заявка одобрена», другой — «Решение не принято: заявку уже решил другой уполномоченный…». В БД одна заявка `approved`, одно списание (баланс 60/0).
3. **Собственная заявка.** Участник с `reward.decide` не видит свою заявку в очереди («Ожидающих чужих заявок нет»); прямой `POST …/decide` отклонён (403/404); в БД `pending`, решающего нет, баланс 90/30.

Снимки `test-results/task-slice/<pid>/reward-decisions-real/`; просмотрен `2-race-b`.

## Замечания

- Фикстура: выдача права в `role_bindings` триггером отзывает сессии пользователя, поэтому сессии создаются после ролей. Это поведение 000004, не дефект теста.
- UX: формулировка конфликта уточнена в `reward-decisions.tsx` (и для выдачи): теперь называет решение другого уполномоченного среди причин; сценарий 2 проверяет новый текст.
