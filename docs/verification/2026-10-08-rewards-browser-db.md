Windows, Node 24.21.0, PostgreSQL 18.6, синтетический кластер `.local/neg-pg` на `127.0.0.1:55444` (база `impuls_neg`, миграции 000001–000031). Сервер собран и запущен `scripts/verify-task-slice.mjs`. Целевой Linux/PostgreSQL 17.6 не проверялся.

## Результат

| Команда                                                                                                                           | Результат                                                                                                            |
| --------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `TEST_DATABASE_URL=postgres://impuls_test@127.0.0.1:55444/impuls_neg node scripts/verify-task-slice.mjs --access-management-only` | exit 0: 11 vitest, 8 mock, 3 access-real, 4 task-flow-real, 3 task-negative-real и новый `rewards-real` — 3 сценария |

`tests/browser/rewards-real.mjs` (cookie-сессии, без `page.route` для API, 390 px; состояние читается из PostgreSQL):

1. **Гонка за последнее место.** Двое участников одновременно подтверждают резерв при квоте 1: один видит «Заявка сохранена», другой — «Обновить условия». В БД одна `pending`-заявка; у победителя 90 доступных/30 в резерве, у проигравшего 120/0.
2. **Отмена и повтор.** Победитель отменяет с причиной: заявка `cancelled`, баллы 120/0. Проигравший после этого резервирует место: статусы `cancelled`+`pending`, у него 90/30, у первого без изменений.
3. **Нет членства в области.** Участник вне области видит «Для каталога требуется членство», позиции нет, баланс 120/0.

Снимки `test-results/task-slice/<pid>/rewards-real/` просмотрен 1-race-loser.

## Замечания

- На форме проигравшего остаётся устаревшее «Свободно: 1» и сверху «Свободных мест больше нет» — сообщение сервера о конфликте в снимке не видно отдельно. Это UX-замечание, не исправлялось.
