# F06: каталог, резерв и отмена — локальные свидетельства

Дата: 03.10.2026, Europe/Moscow. Требования: IMPLEMENTATION_PLAN.md §§ 5–7, 10–12, строка F06. Контракт: [описание среза](../implementation/2026-10-03-f06-reservations-slice.md), [ADR-0008](../adr/0008-synthetic-reward-reservations.md). Это первый срез F06, не завершение функции или R1.

## Подтверждено кодом

- `db/migrations/000017_reward_reservations.js`: immutable reward versions, общий запас квоты на stable reward/scope, непересекающиеся периоды, неизменяемый снимок заявки, unique pending и движения журнала/аудита/outbox. RLS включён, runtime не создаёт/меняет условия каталога; PUBLIC не получает grants. Миграция не создаёт цены, позиции, квоты или полномочия. Forward-only down сохраняет финансовую историю; ADR фиксирует несовместимость старого ledger reader с новыми событиями.
- `packages/domain/src/rewards/write.ts`: текущая сессия и точное synthetic-членство прежде replay; согласованный порядок row locks quota/account/request, проверки после ожидания, атомарный перенос available ↔ reserved, неизменный XP. Повтор одного ключа возвращает прежний ответ, другой body конфликтует. Отмена — только своя pending с причиной/версией, по исходной цене/квоте/сезону, в том числе после отзыва членства для активного участника.
- `packages/domain/src/rewards/read.ts`: только текущая synthetic-область и последняя версия, disabled latest закрывает позицию; active period и только свой признак pending. Личные заявки остаются доступны активному владельцу. Seek-pagination; чтение страниц живое, не общий замороженный снимок.
- `packages/contracts/src/rewards.ts`, `apps/app/src/shared/server/rewards.ts` и четыре Route Handlers: strict schemas, запрет финансовых/субъектных параметров клиента, no-store, origin/CSRF, ограниченный JSON и существующий общий PostgreSQL mutation limit. `SYNTHETIC_REWARDS_ENABLED=false` по умолчанию.
- `packages/contracts/src/ledger.ts`, `packages/domain/src/ledger/read.ts`, `features/ledger/account-ledger.tsx`: reward source без фиктивной задачи; signed available delta, inverse reserve delta, версия условий, причина возврата. Старые acceptance/reversal events сохраняют обязательный task source.
- `features/rewards/reward-catalog.tsx`, `rewards.css`, `features/tasks/task-list.tsx`, `app/globals.css`: пятый личный пункт, каталог/заявки, баланс до/после, обязательное подтверждение, отмена с причиной, общий guard и Telegram Back, ручной replay после неизвестного результата, новый confirmation после 409. Cache refresh каталога/заявок/журнала/профиля. При ошибке обновления свежие операции закрыты, при 401/403 защищённые строки скрыты.

## Неизвестное и следующие решения

Не реализованы decide/reject/fulfill, запрет самоодобрения при будущих решениях, entitlements, автоматическое истечение, изменение/публикация каталога через admin UI и чтение reward events в scoped audit reader. Outbox лишь транзакционно записывается; worker остаётся placeholder, доставка не заявляется. Отмена требует включённого synthetic-флага; выключение флага закрывает весь срез и само по себе не освобождает существующий резерв. Будущий срок резерва требует отдельной политики/миграции.

P-01…P-06, реальные условия/контур, пилот, Supabase/Vercel remote environment, PostgreSQL 17 CI, Telegram Android/iOS и security scan перед пилотом не проверены/не согласованы. Текущие цены/квоты существуют только в тестовых фикстурах. Новые зависимости не добавлялись, bun.lock не менялся этим срезом. Внешний выпуск, commit и deploy не выполнялись; ранее незакоммиченные изменения сохранены. F06/R1 не завершены.
