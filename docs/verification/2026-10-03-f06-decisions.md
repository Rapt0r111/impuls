# F06: решения по синтетическим заявкам — локальные свидетельства

Дата: 03.10.2026, Europe/Moscow. Требования: IMPLEMENTATION_PLAN.md §§ 5–7, 10–12, F06. Контракт: [срез решений](../implementation/2026-10-03-f06-decisions-slice.md), [ADR-0009](../adr/0009-synthetic-reward-decisions.md). Продолжает резерв/отмену ADR-0008; не означает завершение F06/R1.

## Подтверждено кодом

- `db/migrations/000018_reward_decisions.js`: новые terminal approved/rejected с автором/причиной/временем, запрет самоодобрения, исходные условия immutable. Одно завершение резерва в ledger; approve amount=0/reserved_delta=-price, reject amount=price/reserved_delta=-price. Quota reserved уменьшается, used увеличивается только при approve. Runtime не получает DELETE redemptions/INSERT reward versions; PUBLIC не получает прав. Миграция не сеет реальные/синтетические условия или полномочия. RLS и private grants предыдущего среза сохранены. Down сохраняет историю и отказывается разрушать схему.
- `packages/domain/src/rewards/decisions.ts`: только актуальное точное reward.decide, чужая заявка, session recheck до replay и после quota/account/request lock waits. Approve требует активного получателя; reject позволяет освободить резерв выбывшего. Price/latest flag, отзыв membership и окончание quota period не переписывают прежние условия. Decision/balance/quota/ledger/audit/outbox/idempotency — одна транзакция. Ни XP, ни available points при одобрении не изменяются. Отказ возвращает исходную цену один раз.
- Review API не выдаёт Telegram ID, чужие балансы или собственную заявку. GET live seek-pagination сохраняет миллисекундную точность (redemptions timestamps имеют precision 3), выбирает только exact scope и pending. POST принимает decision, expectedVersion и reason; не принимает price/user/actor/status. Origin/session/CSRF/ограниченный JSON/общий PostgreSQL mutation limit предшествуют записи. Оба API private no-store.
- Owner history и личный journal показывают новые статусы и движение резерва. Текущее имя автора решения помечено; stable actor UUID сохранён в БД. Каталог и write-проверка считают approved ещё активной заявкой до будущей выдачи.
- UI: компактная очередь и встроенная форма по выбору пользователя. Сохранённые условия, получатель, исходная цена/период/версия и последствия решения до причины/checkbox. Уход защищает черновик; unknown/429/503/lost response сохраняют точные body/key для manual replay; конфликт оставляет текст и требует возвращения/повторного выбора/подтверждения. Устаревшее чтение запрещает новое решение. Одобрение не заявляет выдачу.

Grant автоматически отзывает сессии существующим DB trigger: синтетическая fixture имитирует повторный вход после grant; тест revoke отдельно восстанавливает лишь тестовую сессию, чтобы проверить отсутствие authority до replay.
- Migration fixture изначально пропустила обязательные ledger timestamps; исправлена. Следующий upgrade test passed.

## Неизвестное и следующие решения

Выдача reward.fulfill и уникальная косметика/entitlements, истечение, отмена после согласования, admin catalog и reward records в scoped audit reader ещё не реализованы. Outbox записан транзакционно; доставка не заявляется. Флаг off закрывает все reward API и сам по себе не освобождает существующие резервы. P-01…P-06, реальные условия/контур, Telegram Android/iOS, assistive technologies на устройствах, PostgreSQL 17 CI, restore drill и security scan перед пилотом остаются непроверенными/неутверждёнными. Внешний release, commit и deploy не выполнялись, bun.lock и зависимости этим срезом не менялись. Ранее незакоммиченная работа сохранена.
