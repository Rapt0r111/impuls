# Проверка безопасности R1 — 2026-10-10

Статический обзор кода `main` (`b68fb4d`) перед закрытым пилотом. Production не зондировался: запросы к развёрнутому сервису не отправлялись. Единственное обращение к Production — чтение Supabase Security Advisor (метаданные, без изменения). Это обзор кода и конфигурации, а не тест на проникновение; ручная проверка в Telegram на Android/iOS не проводилась.

## Итог

Критичных и высоких уязвимостей в коде приложения не найдено. Высокие замечания касались зависимостей (Next.js 16.3.6) и исправлены в этой ветке. Средние M1 и M2 и низкие L1, L3 исправлены по решению владельца; L2 и L4 остаются принятыми рисками.

## Проверено и замечаний нет

- **Вход Telegram** (`packages/domain/src/auth/telegram.ts`): HMAC-SHA256 с ключом `WebAppData`, сравнение `timingSafeEqual`, поле `signature` входит в строку проверки, повторяющиеся ключи отклоняются, срок `auth_date` 10 минут, допуск в будущее 60 с, `user.id` — положительное безопасное целое. `initDataUnsafe` в клиенте не используется.
- **Сессии** (`packages/domain/src/auth/service.ts`, `session.ts`): 256-битный случайный токен, в БД только SHA-256, срок 12 ч, проверка `active` пользователя при каждом чтении, отзыв при выходе. Cookie `HttpOnly; Secure; SameSite=None; Partitioned`.
- **CSRF и Origin**: каждая изменяющая операция проходит одну из общих преамбул (`admin-mutation.ts`, `task-mutation.ts`, `task-management.ts`, `rewards.ts`, `catalog-*.ts`, `quota-publication.ts`, `submissions/[id]/review`, `ledger-corrections`, `auth/logout`) с проверкой точного `Origin`, сессии и HMAC-токена CSRF. Вход ограничен по IP (30/мин) и Telegram ID (10/мин).
- **Права на маршрутах**: все 48 обработчиков в 42 файлах `/api/v1`, кроме самого входа, требуют сессию; права проверяются в доменном SQL по точной области через `role_bindings` с повторной проверкой после блокировок (`task.review`, `reward.decide`, `reward.fulfill`, `ledger.correct`, `admin.*`). История задач доступна только исполнителю или держателю `task.view` в области (`tasks/history-access.ts`). Защищённые права `admin.access*`/`admin.members.manage` нельзя выдать или отозвать через API.
- **SQL-инъекции**: все значения передаются параметрами; интерполируются только константные фрагменты (`permissionPredicate`, `selectTask`, `stamp()`).
- **БД**: приложение работает ролью `impuls_app` без `BYPASSRLS`/`SUPERUSER`; права `PUBLIC` отозваны; все `SECURITY DEFINER` функции имеют `SET search_path=pg_catalog`. Advisor показывает только известные INFO по `pgmigrations` и `profile_name_changes` (политик намеренно нет).
- **Секреты**: в текущем дереве и во всей истории git (55 коммитов) не найдено токенов бота, строк подключения с паролями Supabase, JWT и `sb_secret_`. `.env*` в `.gitignore`, `.env.example` содержит только заглушки.
- **XSS**: `dangerouslySetInnerHTML`, `innerHTML`, `eval` в приложении не используются. Worker отправляет в Telegram только фиксированный текст (`apps/worker/src/telegram.ts`).
- **Логи**: `logFailure` пишет только стадию и класс ошибки, без сообщений и SQL.
