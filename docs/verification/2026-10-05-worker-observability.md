## Независимые ожидаемые результаты

Набор из семи сохранённых синтетических заявок: 2 due pending, 1 future pending, 1 NULL pending, 1 automatic expired, 1 manual expired, 1 approved. Snapshot counts равны `{due:2,scheduled:1,untimedPending:1,automaticExpired:1}`. Earliest due и last automatic decided_at сверены с сохранёнными PostgreSQL датами; возраст сопоставлен с разницей server times с учётом микросекунд/целых секунд. Повторный read и read при удержании quota/balance locks сохраняют checksum всех строк redemptions/quota/balance/ledger/audit/outbox. Dates не заменяют состояние операции.

Проверены app/notification execute denial, caller direct SELECT denial, private owner/STABLE/search_path/PUBLIC ACL, отсутствие executor membership у runtime ролей. Built CLI: flag false до invalid URL, wrong role → exact neutral error/exit 1, status не потребляет queue и не раскрывает IDs. Watch выводит alive и 2 committed expiry, после них due=0/automaticExpired=3; ID участника/заявки/области в output отсутствуют.

Unit lifecycle: empty idle success, monotonic throttling под нагрузкой, отсутствие alive при failed step, stop и once; repeated stop не продлевает deadline; graceful cleanup снимает handlers/timer. Restore сравнивает определения/владельцев/ACL новой функции и после восстановления выполняет automatic return + service-only read; app denial сохраняется. Регрессии сохраняют финансовые инварианты, crash/retry, locks, permissions и прежний HTTP/browser путь. Auto-expiry suite использует `.local/worker-ops-browser` для текущих screenshots; новых UI изменений/приёмки устройств нет.

## Сбои среды и непрошедшие попытки

Первоначальный sandbox запуск PostgreSQL удерживал loopback port, но не отвечал; pg_ctl recovery attempts завершились exit 1. Выявлен точный `postgres.exe` PID 7876 с `-D .local/creation-pg/data`; остановка через pg_ctl не нашла PID, затем завершён только проверенный зависший process. Другие PostgreSQL services не останавливались. Повторный hidden Start-Process вне sandbox с абсолютными workspace paths восстановил тот же synthetic cluster; pg_isready подтвердил accepting connections. Стартовые failures не объявлены успешными. Кластер после проверок остановлен отдельно, data сохранены.

Первый ops integration connect в sandbox получил EACCES, suite failed/9 skipped; повтор вне sandbox прошёл. Первый `bun run build` получил Windows SWC canonicalize access denied (os error 5); та же команда вне sandbox прошла. Первый audit получил DNSResolveFailed, повтор с разрешённым network вернул настоящее advisory. Первая formatter команда с `.env.example` получила no parser; этот файл не заявляется проверенным Prettier, его diff прошёл whitespace check. Failed apply_patch из-за отсутствующего anchor исправлен до проверок; неполного патча в результате нет.

## Подтверждённый dependency риск

`bun pm why braces` показывает dev цепочку `eslint-config-next → @next/eslint-plugin-next → fast-glob → micromatch → braces@3.0.3`. [GHSA-vfj7-8cjw-p6xm / CVE-2026-93687](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) (прочитано 05.10.2026) описывает stack-exhaustion DoS на deeply nested patterns и не указывает patched version. Audit exit 1 сохранён; packages/lock не обновлялись этим срезом, runtime packages не добавлены. Это подтверждённая зависимость/advisory; эксплуатация через приложение и полнота vulnerability scan не проверены. Следующий способ закрытия — подтверждённый upstream fix либо отдельный совместимый переход lint dependency chain с повтором formatter/lint/build, а не фиктивный safe pin или подавление audit.

## Неизвестное / следующий шаг

Три новых POSIX tests добавлены в Linux CI: idle SIGTERM, in-flight drain с ровно одним возвратом и real Node 20 s deadline harness со stalled cleanup. Они пропущены на Windows; workflow не выполнялся удалённо в этой задаче. Deadline harness проверяет production shutdown helper, но не имитирует сетевой stall PostgreSQL. WSL listing в sandbox вернул E_ACCESSDENIED, Docker Linux daemon недоступен; локального Linux rehearsal не было. Целевой PostgreSQL 17.6, systemd-analyze verify/установка/stop/restart/ограничения версии host, фактические alerts/log retention/operator и workload cost aggregates остаются непроверенными.

Runbook thresholds/restart delays — предложенные технические значения synthetic rehearsal. Hosting/реальные credentials не созданы, P-01…P-06 и сроки/экономика не согласованы; Bot API и физические Telegram Android/iOS остаются отдельными срезами. Для status сначала выпустить 000028 и совместимый worker, затем проверить отдельный current_user/TLS; флаги остаются false по умолчанию. Полная приёмка F06/F08/R1 по § 12 не заявляется.
