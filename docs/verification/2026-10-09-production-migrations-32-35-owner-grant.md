## Что сделано

- SQL `up` каждой миграции взят из JS-файла через стаб `pgm.sql` (других конструкций в 000032–000035 нет) и применён отдельной транзакцией через Supabase MCP `apply_migration` с именами `impuls_telegram_delivery`, `impuls_member_management`, `impuls_task_due_reminders`, `impuls_profile_self_name`. К каждой добавлена запись в `impuls_meta.pgmigrations`. Исходные файлы не менялись, адаптаций (как для 000027/000028) не потребовалось: миграции не меняют владельцев объектов.
- Начальная выдача: SQL-эквивалент `scripts/bootstrap-owner.mjs --apply` одним оператором через `execute_sql` (подключения к БД с правами владельца схемы у исполнителя нет). Существующая запись владельца («Владелец (тест)», активна, создана 08.10) оставлена без изменений; создана область `project` «Пилот» и 21 действие с `granted_by` = сам владелец и причиной «Начальная выдача владельцу (scripts/bootstrap-owner.mjs)». Членство владельца в области не создавалось.
