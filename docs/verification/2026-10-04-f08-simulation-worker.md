# F08: проверка локального worker симуляции

Дата: 04.10.2026. Основание: § 8, F08 § 11, режим ожидания § 10 и критерии § 12 `IMPLEMENTATION_PLAN.md`. [Контракт](../implementation/2026-10-04-f08-simulation-worker-slice.md), [ADR-0012](../adr/0012-synthetic-notification-worker.md). Это частичный локальный F08, не приёмка F08/R1.

## Подтверждено кодом

- `db/migrations/000021_notification_simulations.js`: private RLS simulation queue, отдельная NOLOGIN/NOBYPASSRLS роль с колонковым чтением outbox, DB-защита терминального результата, узкая private boolean-функция для lock/read active. Приложение не получает прав на новую очередь, worker — на users, сессии, Telegram ID, тексты, ledger или бизнес-записи. Миграция не обрабатывает outbox, не создаёт цены/допуск/права продукта и не меняет финансы.
- `packages/domain/src/notifications/simulation.ts`: самостоятельный claim с SKIP LOCKED, lease 30 s/token, пять попыток, backoff 30/60/120/240 s, crash recovery, предdispatch/финальная проверка lease, блокировка active через время simulation callback. Fixed text для десяти видов сохранённого события; approval явно не означает fulfillment. Exceptions транспорта превращаются в allowlisted codes, без сохранения raw errors.
- `apps/worker/src/index.ts`: собранный ESM под Node.js, отдельный flag/URL/роль, verified remote TLS, no app-env loader, bounded --once на 20 попыток и --status с агрегатами. Built-in sink возвращает только simulated без сети. Исходный outbox не переводится в sent. Ошибка CLI/idle pool не выводит сырое исключение. По умолчанию нет подключения.
- Новые тесты: `packages/domain/src/notifications/simulation.test.ts`, `tests/integration/notification-simulations.test.ts`. Они работают в disposable `impuls_notifications_<uuid>`, применяют историю миграций и удаляют только проверенную по имени БД. Production/реальные записи не включаются в обработку.
- Зависимости и bun.lock этим срезом не менялись; изменения корневых package/lock уже присутствовали до задачи. Worker build заменён с tsc placeholder на Bun ESM bundling существующего доменного модуля; pg остаётся внешней установленной зависимостью, runtime Node.js. Неиспользуемый `apps/worker/tsconfig.build.json` удалён, strict TS проверяется прежней командой. План/PRODUCT/DESIGN/README, ADR index и next-steps согласованы.

Независимые ожидания: исходное событие после успешной симуляции имеет pending/attempts=0/version=1; simulation имеет simulated/attempts=1 и не вызывается повторно. Два claimers получают разные event IDs, два process одного token вызывают sink один раз, заблокированный due row пропускается. Crash recovery меняет token, старый token не вызывает transport. Пятый crash закрывается failed без блокировки следующего здорового события. Пять транспортных сбоев дают attempts 1…5, delays 30/60/120/240/480 (последняя дата сохраняется, но failed не подбирается). Ошибка сохранения откатывает completion и оставляет исходный lease; повторная симуляция возможна, внешняя exactly-once доставка не заявляется.

Отзыв active после claim или во время ожидания user lock подавляет sink; последующее включение active не переоткрывает suppressed. Отзыв после lock не может завершиться до simulation transaction. Истечение lease во время ожидания получателя даёт lost без sink и без receipt. Зависание fake transport даёт retry/timeout примерно через 5 s и освобождает user lock. Проверены отсутствие прав worker на личные/бизнес-данные, app на simulation queue/function, отсутствие PUBLIC function execute, сохранение outbox/финансов при upgrade и отказ rollback. Реальный Node CLI отключён без DB-соединения по умолчанию, скрывает неверное соединение, запрещает app/owner вместо worker role и обрабатывает только 20 из 22 событий; status показывает два ready и 20 simulated без идентификаторов.
