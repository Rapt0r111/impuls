# F08: проверка жизненного цикла постоянного worker

Дата: 04.10.2026. Основание: § 8, F08 § 11, режим ожидания § 10 и критерии § 12 `IMPLEMENTATION_PLAN.md`. [Контракт](../implementation/2026-10-04-f08-watch-slice.md), [ADR-0013](../adr/0013-synthetic-worker-watch.md). Это локальный технический срез, не приёмка F08/R1.

## Подтверждено кодом

- `apps/worker/src/loop.ts`: serial claim/process, до 20 попыток за пакет, пауза после пакета даже при непустой очереди, прерываемая AbortSignal. Начатый claim завершается и передаётся process; stop запрещает следующий claim. Пауза — digits-only целое 1000–60000 мс, default 5000. Idle не пишет логи, статистика содержит только allowlisted результаты симуляции.
- `apps/worker/src/index.ts`: `--watch`, SIGINT/SIGTERM drain, закрытие пула, 20-секундный защитный deadline, нейтральный exit 1 на DB/idle pool error. Нет внутреннего reconnect или автоматического запуска. Старые `--once`/`--status`, disabled без подключения, отдельная роль/URL, verified TLS и встроенный local sink сохраняются.
- `package.json`: `worker:watch` запускает Node entry point; `test:notifications` включает новый lifecycle unit suite. `.env.example` объясняет poll interval. Никаких новых runtime зависимостей/миграций; `bun.lock` этим срезом не менялся. Бизнес-домен, API, UI, экономика и исходные события не меняются.
- `apps/worker/src/loop.test.ts`, `tests/integration/notification-simulations.test.ts`: семь lifecycle unit сценариев, PostgreSQL drain и реальные Node CLI/idle/crash/connection-loss сценарии. Disposable DB имеет проверенное имя `impuls_notifications_<uuid>`; тесты применяют 000001–000021 и удаляют только созданную ими БД. POSIX signal test явно skipped на Windows.
- План, PRODUCT, DESIGN, README, ADR index и next-steps описывают этот локальный срез. Предшествующие изменения рабочего дерева сохранены; удалённый контур и реальные данные не использовались, коммит/деплой не выполнялись.
- `tests/browser/rewards.mjs`: вспомогательный keyboardRefresh ждёт включения кнопки перед focus/Enter. После повторного открытия раздела сохранённый error text может появиться раньше окончания запросов; focus(), в отличие от click(), не ждёт enabled. Продуктовый UI не менялся.

В PostgreSQL/HTTP этапе общего запуска был нейтральный 503 log отрицательного сценария; assertions прошли. Прежний MODULE_TYPELESS_PACKAGE_JSON warning helper сохранился; package type приложения не менялся.

Независимые ожидания: empty queue не создаёт результатов; once выполняет 20, watch делает паузу и затем 21-ю попытку. Stop во время claim завершает именно его. Stop во время PostgreSQL simulation callback оставляет первое событие simulated/attempts=1, второе ready/attempts=0; оба исходных outbox pending/attempts=0. Реальный Node watch дважды замечает события после idle без перезапуска и не выводит recipient/event IDs или private source text. Kill во время ожидания recipient lock оставляет processing/attempts=1; новый Node до lease expiry возвращает пустые results, после срока получает simulated/attempts=2, исходное событие pending/attempts=0/version=1. Принудительный pg_terminate_backend даёт exit 1 / WORKER_UNAVAILABLE без URL/личных данных и без reconnect. Прежние ACL, suppression, backoff, rollback, terminal guard и domain lease tests сохранились.

## Аудит зависимостей и источники

В общем browser harness каталог остановился с Timeout 30000ms на `Оформить заявку` после keyboard refresh. Узкий `test:task-slice --rewards-only` воспроизвёл состояние: временный probe показал catalog-denied / refresh enabled=false перед focus; дополнительная задержка probe позволила сценарию пройти (timing-sensitive). Исправление ждёт enabled перед клавиатурным действием, сохраняя проверку Enter и восстановления с первой страницы. Probe `[DEBUG-f08-watch]` удалён. `bunx eslint apps/worker/src tests/integration/notification-simulations.test.ts tests/browser/rewards.mjs` — exit 0. Применён `diagnosing-bugs`: отдельный repro, три гипотезы, targeted probe, исправление синхронизации теста и scoped rerun. Пауза refresh из-за незавершённой загрузки была подтверждена; изменение продуктового кода не потребовалось.

`bun audit --json` в sandbox сначала не смог подключиться к npm registry (ConnectionRefused). Повтор той же read-only команды с разрешённым сетевым доступом выполнен: exit 1, один high advisory [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm), braces <=3.0.3. Проверенный lockfile содержит braces@3.0.3; `bun pm why braces` (exit 0) показывает цепочку braces → micromatch → fast-glob → @next/eslint-plugin-next → eslint-config-next (dev). Advisory на дату проверки указывает отсутствие patched version. Зависимость не обновлялась/не подавлялась; это открытый риск dev toolchain, полная оценка достижимости не выполнена. Чистый dependency audit не заявляется.

Применён `supabase:supabase`: сохранены private схема, отдельная роль, минимальные права и проверки инвариантов PostgreSQL. Текущие первичные [connection docs](https://supabase.com/docs/guides/database/connecting-to-postgres) проверены; changelog.md web-инструмент не прочитал из-за unsupported text/markdown. Новые Supabase возможности/пакеты не используются. [Node.js 24 signal docs](https://nodejs.org/docs/latest-v24.x/api/process.html#signal-events) подтверждают различие Windows kill и graceful POSIX signals; [timers docs](https://nodejs.org/api/timers.html#timers-promises-api) описывают прерываемую паузу. Реальная совместимость подтверждается локальным Node v24.21.0. Frontend/React/Next skills не применялись: UI/Route Handlers не менялись.

## Что осталось неизвестным или требует решения

POSIX SIGTERM test не исполнялся на Windows; Linux CI в этой задаче не запускался. Поведение защитного 20-секундного принудительного завершения требует отдельного fault test на целевом хосте. Graceful stop проверен через AbortSignal с действительной PostgreSQL; actual OS signal acceptance этим не подменяется. Hosting/supervisor/restart backoff, реальные role credentials/remote TLS, нагрузка и backup restore не проверены.

Открыты Bot API adapter/consent/неоднозначный исход/429/403, admin delivery UI, reminders/season events, автоматическое истечение F06, физические Telegram Android/iOS, внешнее развёртывание и P-01…P-06. Flag проверяется только при запуске: работающий watch сначала останавливают. Квитанция simulated не означает сообщение. F08/R1 не объявляются завершёнными.
