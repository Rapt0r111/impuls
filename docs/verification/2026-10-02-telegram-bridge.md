## Что проверено браузером

- Insets top 24+48, bottom 34+16, left 26+4, right 18+12 приводят к ожидаемым CSS-отступам; основной интерфейс не выходит по горизонтали на четырёх ширинах.
- Смена темы Telegram на light сохраняет собственную navy-тему и повторно задаёт три native цвета. Промежуточный viewport не меняет стабильный минимум; завершённое изменение меняет его. Смена отступов/уменьшение viewport сохраняет прокрутку к действию формы.
- SDK без новых API и SDK с исключениями presentation-методов позволяют открыть и закрыть задачу обычными UI-кнопками.
- Два сценария SDK после 12 секунд: открытая пустая деталь сохраняется; черновик, введённый до подключения, тоже сохраняется и получает native closing confirmation.
- Native Back при отказе от потери текста сохраняет форму, текст и кнопку; подтверждение закрывает форму. Вложенные исправления закрываются в порядке форма → панель → раздел. Аналогично проверены очередь и редактирование.
- Повторные открытия не множат native Back listeners; после серверного 403 рабочие данные удаляются, listener отсутствует, кнопка скрыта, старый callback не действует.

Четыре снимка находятся в [assets/telegram-bridge](assets/telegram-bridge). Просмотрены фактически отрендеренные [320 px](assets/telegram-bridge/safe-320.png) и [1280 px](assets/telegram-bridge/safe-1280.png): прежняя типографика/палитра сохранены, форма и кнопки укладываются в доступную ширину, крупные synthetic insets видны как свободные поля. ## Сбои, исправления и границы доказательств

Первый check остановился на React lint: callback ссылался на queue/query до объявления. Hooks перенесены после query, а native и видимые Close используют одну функцию. Следующий check обнаружил присваивание undefined optional-полю test fixture при exactOptionalPropertyTypes; fixture исправлен через delete. Финальный check прошёл.

Повторный browser-прогон выявил timeout позднего SDK: ранее onReady повторно включал экран проверки входа и размонтировал уже открытую деталь. Исправлен сам путь подключения для подтверждённой сессии, затем добавлены независимые сценарии пустой детали и существующего черновика. Финальный набор из 14 сценариев прошёл на новой production-сборке. Регрессионные 93 сценария выполнены до этой последней правки позднего подключения; их immediate-SDK путь не менялся, повторно они не запускались.

Не проверены физические Telegram Android/iOS, реальные fullscreen/поворот/клавиатура, системное увеличение текста в нативном клиенте, native контраст/жесты и screen readers. Суммирование device/content insets — проверенная локальная политика, её фактические значения надо сверить на этих устройствах. SDK-симуляция не доказывает поддержку всех API установленными Telegram-клиентами. Не исполнялись PostgreSQL-интеграция, итоговый security scan, восстановление, измерение производительности и новый удалённый CI. Пилот, F01/F03/F05/R1 и P-01…P-06 не объявлены завершёнными.

Применены `vercel:nextjs` (прочитан также локальный Next use-client guide) и `vercel:react-best-practices`: client-only SDK boundary, cleanup native подписок, актуальные callbacks без повторных native listeners, отсутствие новых data-fetch waterfalls и сохранение семантических контролов. Визуальные tokens и структура сверены с DESIGN.md; отдельный redesign/Impeccable polish не запускался. Единственный внешний API-источник — [официальная документация Telegram Mini Apps](https://core.telegram.org/bots/webapps), прочитана 02.10.2026; использованы WebApp events, BackButton и safe-area/viewport поля, адаптированные к существующим React/CSS. Новых зависимостей нет.

Следующие открытые работы по плану: F05 уровни/профиль и уникальное «Первый результат», затем каталог/заявки и worker. Перед реальным пилотом остаются P-решения и устройство/эксплуатационная приёмка.
