## Подтверждено файлами

- `db/migrations/000027_automatic_reservation_expiry.js`: независимые NOLOGIN caller/executor, фиксированный definer search_path, off-by-default automatic source, нет backfill дат/людей/полномочий. Caller имеет только USAGE/EXECUTE без параметров, app и notification worker — без EXECUTE; executor не получает bypass RLS/CREATE или права корректировки/выдачи. Provenance trigger запрещает app impersonation. RLS записей ограничены expiration. Прежние human decisions сохраняются.
- `packages/domain/src/rewards/automatic-expiry.ts`: disabled возвращается до обращения к pool; один SQL-вызов возвращает boolean. Locks quota→balance→redemption, после ожидания server clock/current state. Исходная price/quota/season и inverse ledger, audit/outbox атомарны; XP/used сохраняются, NULL/future/terminal не меняются. UNIQUE resolution и status обеспечивают однократность.
- `apps/worker/src/index.ts`, `loop.ts`: отдельные `--expire-once`/`--expire-watch`, независимый false flag, отдельная runtime роль, прежние TLS/stop/deadline/нейтральные ошибки, bounded 20 operations/poll. Общий loop сохраняет drain уже полученной notification claim. Нет Bot API или автоматического назначения срока.
- `packages/domain/src/rewards/shared.ts`, `admin/audit.ts` и wire contracts: null actor обозначает только automatic expired с fixed reason/name; owner/exact-scope audit читают сохранённый результат. Existing UI `reward-catalog.tsx` показывает обработчик и уточняет, что часы устройства не подтверждают возврат. Новый экран/CSS/зависимость не добавлены.
- `tests/integration/database-restore.test.ts`: owner+ACL сохраняются, schema/table/function owners сравниваются явно, negative owner drift замечается; новая операция работает через восстановленный definer. Два прежних trigger guards используют явные ветки, не требуя несвязанных SELECT при generic plan.
- План, PRODUCT, DESIGN, README, ADR index, next steps и restore contract синхронизированы. Исторические записи о ручном-only истечении сохранены с маркировкой исторического статуса.

## Проверенные сценарии и обнаруженные ошибки

Независимая сверка: 120 available → 97 available + 23 reserved → 120 + 0, quota.reserved 1→0, used=0, XP=300. Две ledger/audit/outbox записи на заявку (reserve и единственная resolution), исходные price/season/time zone. Проверены revoked recipient, NULL/future, locked quota, late approve/earlier approved terminal, два workers, manual cancel/reject/expire races, rollback при outbox failure и identical next pass. Crash во время balance wait не выдаёт второй возврат; backend может кратко удерживать quota после disconnect, следующий проход подтверждает результат. Watch обнаруживает позже созданный срок и пишет только neutral counts.

Оригинальный sandbox DB connect дал EACCES; запуск вне sandbox подтвердил ECONNREFUSED после остановки sandbox descendants, затем hidden persistent cluster решает ограничение. Initial Next build получил Windows canonicalize os error 5; повтор вне sandbox прошёл. Общий unit runner сначала получил ENOENT временных SSR-модулей из sandbox TEMP; workspace TEMP/TMP исправили выполнение. Эти попытки не объявлены успешными.

Первые DB-проверки выявили SELECT к entitlements/ledger_corrections из прежних combined trigger expressions после перехода к generic plan. Исправлены явные SQL-ветки, несвязанные SELECT executor не выдавались. Fixture sessions после permission grants были отозваны существующим trigger; tests создают допустимую сессию после grants. SET ROLE denial нельзя доказывать через superuser session_user — проверено отсутствие SET membership через pg_has_role, direct table/execute denial проверены с runtime current_user.

Первый restore с --no-owner заметил ACL/owner drift и отказ automatic provenance. Удалён --no-owner, owners стали явной частью snapshot и отрицательного контроля; все 9 сценариев повторно прошли. Formatter выявил automatic-expiry test formatting; файл отформатирован перед финальной проверкой.
