# F03: чтение назначенных задач — 29.09.2026

## Подтверждено исходниками

- `db/migrations/000006_assigned_tasks_read.js` создаёт версии правил, задачи и одно назначение на задачу для R1. Новые таблицы находятся в закрытой схеме `impuls`, имеют RLS и только право `SELECT` для `impuls_app`. В миграции нет данных реальных участников и правил P-04.
- `packages/domain/src/tasks/read.ts` выбирает только задачи, назначенные активному пользователю. Список ограничен 50 строками и использует курсор по UUID; чужая деталь возвращает `null` доменному адаптеру. Действие `task.review` пока не открывает чтение чужих задач.
- `packages/contracts/src/tasks.ts` описывает запрос списка и ответы; Route Handlers `GET /api/v1/tasks` и `GET /api/v1/tasks/:id` требуют текущую сессию и возвращают `private, no-store` через общий HTTP-адаптер. Для чужой или неизвестной детали возвращается одинаковый 404.
- После входа `apps/app/src/features/tasks/task-list.tsx` показывает список, фильтр состояния и критерии выбранной задачи. Данные приходят только из API через TanStack Query; прототип `work/*` не импортируется.

## Не проверено

- `000006` не применена к локальной или выбранной удалённой PostgreSQL: `TEST_DATABASE_URL` не задан, а локальные `psql`, Docker и `pg_ctl` не обнаружены. Новые integration-тесты находятся в репозитории, но не исполнялись. Следующая проверка — миграция и `bun run test:integration` в отдельной PostgreSQL 17.6 CI-среде, затем SQL-проверка RLS/грантов и отрицательный запрос к Data API.
- Route Handlers не проверены сквозным запросом к БД; браузерный сценарий подменяет ответы. Не проверены Telegram Android/iOS, клавиатура WebView, смена темы, системное увеличение текста и реальная производительность.
- Создание/назначение, сдача, возврат, приёмка и начисление ещё отсутствуют. Поэтому F03/F04 и R1 не соответствуют критериям §§ 11–12. Реальные поля/правила и пилот зависят от P-01…P-06.
