# F07: локальная публикация будущего периода квоты

Дата: 05.10.2026. Основание: IMPLEMENTATION_PLAN.md §§ 4–7, 10–12, F02/F06/F07; [контракт](../implementation/2026-10-05-f07-quota-publication-slice.md), [ADR-0017](../adr/0017-synthetic-quota-publication.md). Это локальный синтетический срез, не внешний выпуск или приёмка R1.

## Подтверждено файлами

- `db/migrations/000025_quota_publications.js`: отдельное `admin.catalog.quota.publish`, column INSERT только параметров новой quota; append-only журнал с immutable dates/capacity, actor/request/reason. Runtime не получает UPDATE capacity/dates/DELETE или INSERT counters; worker/PUBLIC не получают доступа. Миграция не назначает пользовательские права.
- `packages/contracts/src/quota-publication.ts`: strict body/response, canonical UTC с миллисекундами, положительная длина интервала, capacity 0–1000000, непустое основание. Это технические границы синтетического ввода, не утверждённые реальные квоты.
- `packages/domain/src/admin/publish-quota.ts`: active actor → exact permissions → session → idempotency → прежний identity advisory lock → quota rows в стабильном порядке. После ожидания перечитываются права/сессия/дата, перед commit — права/сессия. Период, основание и ответ атомарны. Пересечения запрещены доменом и прежним DB trigger. Replay сохраняет исходный snapshot, включая после начала периода; прежние reserved/used, баланс и pending snapshot не переносятся.
- `apps/app/src/shared/server/quota-publication.ts` и `api/v1/admin/rewards/[id]/quotas/route.ts`: POST в Node.js, no-store, Origin/content-type/размер/strict query/header/body/CSRF, прежний общий actor limiter. Оба default-false флага и два точных права обязательны. GET сохраняет прежний контракт. `admin/catalog.ts` возвращает canPublishQuota как affordance, POST проверяет реальные права независимо.
- `packages/domain/src/admin/audit.ts`, `packages/contracts/src/audit.ts`, `features/audit/audit-log.tsx`: exact-scope `quota.publish`, независимый audit flag/permission, неизменяемый snapshot вместо live counters. Ответы прежних действий имеют default null quota, прежняя история не реконструируется.
- `features/catalog-admin/quota-publish.tsx`: пользователь выбрал закрытую форму под позицией; UTC подписи/объяснение, capacity/reason, preview и отдельное подтверждение. Unknown/503/429 замораживают body/key для ручного повторения; конфликт/422 блокируют intent до закрытия и нового чтения. Dirty/Back, denial cache clearing/cancel и игнорирование late response. Используются прежние CSS/tokens/dependencies; исправлен устаревший текст о read-only квотах.
- `scripts/verify-task-slice.mjs`: новый integration/browser suite включён и в `--admin-catalog-only`, и в полный прогон. `database-restore.test.ts` создаёт quota publication перед dump и проверяет immutable history/replay после restore. Документы плана/продукта/дизайна/ADR/README/next steps согласованы с локальным статусом.

Ожидаемые результаты независимы от расчётов реализации: будущая capacity=3/reserved=0/used=0, прежний pending резерв и его balance/snapshot сохраняются. Два разных publisher intent дают один успех/один overlap; два одинаковых intent дают один сохранённый ответ и одну запись. Смежный период разрешён, capacity=0 не получает места. После наступления нового периода reserve capacity=1 занимает ровно одно место, replay publication не обнуляет его. Проверены строгие UTC/counter/policy границы, чужая область/нет identity/reader/terms-publisher без отдельного quota права/flag/invalid session/active revoke, rollback audit failure, immutable owner trigger/runtime ACL, filtered audit и следующая страница без повтора.

Lock tests наблюдают `pg_blocking_pids` до отпускания blocker и проверяют истечение permission/session/start date после ожидания quota barrier. HTTP/browser-to-DB проверяют настоящий сервер: Origin/CSRF/content-type/idempotency/body/query/413/405, 201/no-store/replay, затем второй период из реальной формы. Browser fixtures дополнительно проверяют 320/360/390/1280, preview/success, retry abort/503/429 с тем же key/body, conflict/422, 401/403/404, read-only affordance, dirty Back accept/dismiss, late scope response, fractional input/keyboard, enlarged text и audit snapshot.

Семантика транзакционных advisory/row locks сверена с [PostgreSQL 17 Explicit Locking](https://www.postgresql.org/docs/17/explicit-locking.html). Next Route Handlers сверены с установленным `node_modules/next/dist/docs/01-app/01-getting-started/15-route-handlers.md`. Новых зависимостей нет.

## Сбои промежуточных прогонов

Первые попытки старого sandbox PostgreSQL :55432 дали EACCES/ETIMEDOUT, поэтому проверки перенесены в новый изолированный :55433 вне sandbox. Начальная Next.js сборка в sandbox упала на Windows canonicalize baseUrl/access denied; повтор вне sandbox прошёл. Первый unit прогон получил ENOENT общего sandbox TEMP у 40 suites; повтор с workspace TEMP/TMP прошёл. Начальный typecheck заметил повторный POST export и недостающую подпись нового permission — исправлено. Линтер заметил пять unused destructuring переменных в тесте — исправлено. Прежний HTTP тест GET-only квоты ожидал POST405; теперь корректно проверяет POST403 без trusted Origin, PUT405 проверяется новым suite. Первый HTTP прогон: 1 failed/30 passed; финальный: 32 passed. Сбои не считаются пройденными проверками.

Промежуточные `format:check` выявляли форматирование route, review и изменённой таблицы отчёта; затронутые файлы обработаны Prettier, повтор прошёл.

## Неизвестно / требует владельца

Удалённый PostgreSQL 17.6 Linux CI, full `test:task-slice` без фильтра, реальный Telegram Android/iOS, мобильная клавиатура/screen reader/OS scaling, нагрузка/performance, внешний выпуск и security scan перед пилотом этим срезом не выполнены. Dependency audit/переустановка не выполнялись: dependencies/lockfile этим срезом не меняются. Restore — same-cluster synthetic rehearsal, не RTO/PITR нового Supabase проекта. Существующие периоды не редактируются/не отменяются, identity не создаётся, реальные цены/квоты/служебные поощрения не утверждены. P-01…P-06 и полная приёмка F07/R1 открыты. Следующий предметный срез — создание synthetic cosmetic identity с отдельным контрактом.
