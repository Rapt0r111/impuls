Windows, Node 24.21.0, PostgreSQL 18.6, синтетический кластер `.local/neg-pg` на `127.0.0.1:55444` (база `impuls_neg`, миграции 000001–000031). Сервер собран (`bun run build:app`) и запущен `scripts/verify-task-slice.mjs`. Целевой Linux/PostgreSQL 17.6 не проверялся.

## Результат

| Команда                                                                                                                           | Результат                                                            |
| --------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| `TEST_DATABASE_URL=postgres://impuls_test@127.0.0.1:55444/impuls_neg node scripts/verify-task-slice.mjs --access-management-only` | exit 0: все прежние проверки и новый `task-return-real` — 2 сценария |

`tests/browser/task-return-real.mjs` (cookie-сессии, без `page.route` для API, 390 px; состояние читается из PostgreSQL):

1. **Возврат, доработка, повторная сдача, приёмка.** Проверяющий возвращает отчёт с причиной: задача `needs_work`, 1 проверка, начислений 0. Исполнитель видит причину, нажимает «Продолжить работу», сдаёт исправленный отчёт: `in_review`, 2 отчёта, начислений по-прежнему 0. Приёмка: `accepted`, 2 проверки, ровно 2 записи журнала (17 XP, 9 баллов).
2. **Чужая задача.** Не назначенный участник не видит задачу в списке; прямые `GET`, `PATCH start` и `POST submissions` отклонены (403/404); в БД `assigned`, отчётов, проверок и начислений нет.

Снимки `test-results/task-slice/<pid>/task-return-real/` созданы; визуально не просматривались.

## Не проверено

- Идемпотентный повтор с тем же/другим телом в браузере (покрыт интеграционными тестами).
- Только 390 px; 320/360, увеличенный текст, Telegram WebView.
- Фикстуры не удаляются (случайные идентификаторы в изолированной базе).
- Linux/PostgreSQL 17.6 CI, Android/iOS, P-01…P-06, приёмка R1 открыты.
