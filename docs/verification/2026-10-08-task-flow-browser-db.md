## Результат

| Команда                                                                                                                                    | Результат                                                                                              |
| ------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| `TEST_DATABASE_URL=postgres://impuls_test@127.0.0.1:55444/impuls_cancellation node scripts/verify-task-slice.mjs --access-management-only` | exit 0: 11 vitest, 8 mock-сценариев, 3 access-real, новый `tests/browser/task-flow-real.mjs` — 4 этапа |

Этапы `task-flow-real.mjs` (три отдельные сессии с cookie, без `page.route` для API):

1. Постановщик (390 px) создаёт черновик и назначает исполнителя; в БД статус `assigned`.
2. Исполнитель начинает работу и отправляет отчёт; в БД `in_review`, одна сдача, XP и баллы по задаче 0 (до приёмки начислений нет).
3. Проверяющий принимает результат с основанием и подтверждением; в БД `accepted`, одна проверка, ledger по задаче 17 XP и 9 баллов.
4. Исполнитель видит «+17 XP» и «+9 баллов»; `account_balances` = 17 XP / 9 доступных / 0 в резерве, как сумма журнала.

Приёмка включается только если определение правил содержит `timeZone` и `acceptance.enabled` (`packages/domain/src/ledger/economy.ts`); фикстура задаёт их явно.
