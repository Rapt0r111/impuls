## Результат

| Команда                                                                                                                           | Результат                                                                                                                              |
| --------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `TEST_DATABASE_URL=postgres://impuls_test@127.0.0.1:55444/impuls_neg node scripts/verify-task-slice.mjs --access-management-only` | exit 0: 11 vitest, 8 mock-сценариев, 3 access-real, 4 этапа task-flow-real и новый `tests/browser/task-negative-real.mjs` — 3 сценария |

Сценарии `task-negative-real.mjs` (сессии с cookie, без `page.route` для API, ширина 390 px, состояние проверяется запросами к БД):

1. **Собственный результат.** Участник с правом `task.review` в той же области не видит свой отчёт в очереди; прямой POST на `/submissions/{id}/review` возвращает 403/404; в БД статус `in_review`, проверок 0, записей журнала 0.
2. **Две одновременные приёмки.** Два проверяющих открывают один отчёт и нажимают «Принять» одновременно: один видит «Результат принят», другой — «Решение уже изменилось…» (409). В БД `accepted`, одна проверка, две записи журнала, 17 XP и 9 баллов ровно один раз.
3. **Отзыв доступа при открытой форме.** После `users.active=false` отправка закрывает рабочий экран («Доступ отозван»); в БД задача остаётся `in_review`, проверок и начислений нет.

Снимки `test-results/task-slice/<pid>/task-negative-real/` просмотрены для сценариев 2 (проигравшая сторона) и 3.

## Не проверено

- Повтор запроса с тем же и другим телом (идемпотентность) в браузере; её покрывают интеграционные тесты.
- Чужая задача для исполнителя, возврат на доработку и повторная отправка в этом наборе не участвуют.
- Только 390 px; 320/360, увеличенный текст и Telegram WebView не проверялись.
- Фикстуры не удаляются (случайные идентификаторы в изолированной базе).
- Linux/PostgreSQL 17.6 CI, Android/iOS, P-01…P-06, приёмка R1 открыты.
