# F05: проверка локального профиля и первого результата

Дата: 02.10.2026, Europe/Moscow. Требование: IMPLEMENTATION_PLAN.md §§ 5, 7, 10–12, строка F05. Контракт: ADR-0006 и `docs/implementation/2026-10-02-f05-profile-slice.md`.

## Подтверждено файлами и кодом

- `db/migrations/000015_first_result.js`: одна выдача на пользователя, проверенный источник XP-приёмки, версия условия, время и происхождение. Исторические выдачи восстановлены по timestamp/UUID, без добавления валюты. Runtime не имеет UPDATE/DELETE; RLS включён, PUBLIC/API-grants отозваны. Откат после новых выдач запрещён.
- `packages/domain/src/ledger/credit.ts`: выдача после блокировки баланса в общей транзакции приёмки. Повторы/другие принятые задачи не добавляют второе достижение. Ошибка последующего аудита откатывает review, валюты и выдачу.
- `packages/domain/src/profile/progression.ts`, `profile/read.ts`: собственный профиль, snapshot баланса/правил/источника и повторная проверка истечения сессии. Уровни только по явно заданным синтетическим порогам. Последняя действующая конфигурация с progression выбирается по effective_from/version/UUID; некорректная новая версия не подменяется старой. Коррекция меняет текущий уровень и помечает исторический источник, не перевыдавая достижение.
- `packages/contracts/src/profile.ts`, `apps/app/src/app/api/v1/me/profile/route.ts`: проверенный wire-формат, no-store, серверный субъект без параметров чужого пользователя, выключенный по умолчанию SYNTHETIC_PROFILE_ENABLED.
- `apps/app/src/features/profile/participant-profile.tsx` и `.css`, `features/tasks/task-list.tsx`: профиль в существующем workspace, защита несданного отчёта/native Back, подписанный progress, XP/уровень/остаток/основание и timestamp. Loading/empty/unconfigured/invalid/maximum/corrected/migration/disabled/error/stale/offline/revoked/session проверяются браузером. Неподтверждённый результат не подменяется демонстрационными данными в приложении.
- `.github/workflows/check.yml`: обычный check получает пустой TEST_DATABASE_URL. Полный PostgreSQL/HTTP-набор выполняется позднее через test:task-slice с HTTP-сервером. Удалён прежний standalone integration-шаг без сервера; локальный сбой доказал его несовместимость с существующим HTTP-тестом корректировок. Изменённый GitHub CI удалённо не запускался.

### Встреченные сбои и исправления

- Первый sandbox-запуск pg_ctl без параметров порта: restricted-token error 87; БД не запущена, migration получила ECONNREFUSED. Разрешённый запуск без `-o` затем получил OS socket permission error для localhost. По журналу установлен запуск с выделенным 127.0.0.1:55432; он успешен. Automatic approval review действие не отклоняла.
- Первая проверка коррекции ожидала singular allowSyntheticCorrection; фактический доменный контракт использует allowSyntheticCorrections. Исправлена фикстура, повтор прошёл.
- Первый check с TEST_DATABASE_URL без HTTP-сервера: существующий `ledger-corrections.test.ts` сообщил `Run bun run test:task-slice`. Повтор check без адреса БД и полный runner с сервером прошли. CI приведён к этому порядку.
- Первый HTTP-тест отозванной сессии ожидал 401; существующий адаптер readSession возвращает revoked/403. Исправлено ожидаемое значение по фактическому контракту, повтор прошёл. Обе категории 401/403 скрывают профиль.
- Документация Next.js первоначально искалась с `.mdx`; установленная версия хранит `.md`. Прочитаны реальные локальные `15-route-handlers.md` и `route.md` перед окончательной проверкой.

Ожидаемый API 503 из отрицательного теста лимитера и существующий Node MODULE_TYPELESS_PACKAGE_JSON для session-cookie.ts присутствовали в полном прогоне; команды завершились успешно. Это не скрытые падения.

## Источники и предел доказательств

Использованы frontend-references, Impeccable (context/detect/provenance + независимые reviewer/documenter), vercel:nextjs, vercel:react-best-practices и Supabase skill/docs connector. Первичные справочники: [PostgreSQL 17 INSERT/ON CONFLICT](https://www.postgresql.org/docs/17/sql-insert.html), [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), локальные Next.js 16.3.6 docs; [официальный route reference](https://nextjs.org/docs/app/api-reference/file-conventions/route) использован как дополнительный. Supabase changelog.md не удалось прочитать: web отказала по text/markdown, shell — по socket policy. Новых Supabase API/SDK здесь нет; PostgreSQL-примитивы проверены локально. Это не подтверждает весь внешний Supabase-контур.

Предложено/зафиксировано для теста: версия условия достижения, историческое сохранение исправленного источника и пересчитываемый уровень. Требует владельца: P-04 для реальных порогов/отзыва, P-05 для видимости, остальные P-01…P-06 для пилота. Не проверены PostgreSQL 17.6 CI, реальная доставка уведомлений, Android/iOS Telegram и screen readers; performance SLO и recovery перед пилотом. Не реализованы сезонные snapshots/errata и R2-вехи. F05/R1 не объявлены завершёнными.

Нет git commit/push, внешних миграций, выпуска Supabase/Vercel или реальных начислений. Все предшествующие изменения рабочей копии сохранены; этот отчёт описывает новый профильный срез.
