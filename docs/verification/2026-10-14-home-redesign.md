# Главная по макету «NR_Point Home» и скрытие пустых кнопок (14.10.2026)

Только фронтенд: без миграций, без изменений серверных контрактов.

## Что изменено

- **Главная** (`apps/app/src/features/home/home.tsx`, `home.css`) приведена к макету владельца (артефакт «NR_Point Home»): шапка со знаком и названием, приветствие с бегущим кольцом аватара, карточка «Ближайший срок» с орбитой, две плитки (XP с уровнем и баллы), строка месяца с пульсирующей точкой. Данные те же, что и раньше (профиль, задачи, рейтинг); цвета берутся из токенов приложения.
- Акцентный шрифт макета Unbounded Bold (SIL OFL 1.1, @fontsource/unbounded 5.3.0) лежит локально рядом с Manrope: `apps/app/src/shared/ui/fonts/` (кириллица и латиница, 34 КБ, лицензия в `Unbounded-OFL.txt`). Внешних запросов за шрифтами нет.
- **Кнопки без дела убраны.**
  - Главная: без открытых задач нет кнопки «Все задачи»; карточка очереди проверки и «Открыть очередь» видны, только когда в очереди есть отчёты (или число не загрузилось). Очередь по-прежнему открывается через «Ещё».
  - «Задачи»: без единой задачи нет переключателя «Активные / Проверка / Готово».
  - «Очередь проверки», «Решения по заявкам» и «Выдача поощрений», «Постановка задач», «Баланс и журнал»: кнопка «Обновить…» не показывается, пока список пуст (при ошибке загрузки кнопка «Повторить» остаётся).
  - Кнопки действий над задачей и заявкой уже зависели от статуса и доступности; их не меняли.

## Дополнение: живое обновление, полный экран, пустые плашки

- **Данные обновляются сами.** `QueryClient` в `apps/app/src/features/tasks/task-list.tsx` перезапрашивает открытые на экране данные раз в минуту, пока приложение на виду и пользователь что-то делал последние 5 минут; без касаний опрос засыпает и просыпается первым касанием (с мгновенным обновлением). Также данные обновляются при возвращении в приложение и при появлении сети. В фоне запросы не идут. Экраны каталога (`catalog-admin`, `catalog-history`, `catalog-quotas`) намеренно не обновляются сами, как и раньше. Это опрос, а не push: новая задача появляется до минуты позже, а не мгновенно. Мгновенные обновления потребуют серверной части (Supabase Realtime или SSE) и отдельного решения.
- **Полный экран на телефонах.** `apps/app/src/shared/telegram/web-app.tsx`: на Android и iOS при Bot API ≥ 8.0 вызывается `requestFullscreen()`, при ≥ 7.7 отключается закрытие свайпом вниз. На компьютере и в вебе окно прежнее. Если клиент не поддерживает методы, вход не страдает. Отступы под системные кнопки уже обрабатывает `environment.ts` (safe area). Постоянный полноэкранный запуск без `requestFullscreen` включается в BotFather («Configure Mini App», размер Full-size) — это настройка бота, не код.
- **Пустые плашки убраны.** Без открытых задач карточки «Ближайший срок» на «Главной» нет совсем; пустые списки (задачи, очередь проверки, решения, журнал, каталог, постановка задач) показывают короткую подсказку без плашки (`.tasks-empty`). Тексты на «Главной» уменьшены: имя 20, название задачи 18, значения плиток 28 px; плитки XP и баллов всегда в два столбца, как в макете.
- Тесты: новый `tests/browser/live-refresh.mjs` (задача появляется без перезагрузки на «Главной» и в «Задачах»; `requestFullscreen` вызывается на ios и android и не вызывается на tdesktop и weba). `home.mjs`: после возврата сети данные обновляются без нажатия «Повторить».
- Не проверено: реальный Telegram на Android и iOS (полноэкранный режим и отступы), нагрузка опроса на Vercel и Supabase при многих участниках.

- **Нижняя навигация** приведена к макету: капсула 72 px с размытием, пять равных колонок, таблетка 56×30, свечение значка активного раздела, всплытие при открытии, лёгкое парение таблетки и отскок значка при выборе; подписи на 320 px уменьшены, чтобы «Поощрения» не переносилось.

## Перенос обновлённого макета «Главной» (макет перечитан 2026-10-14)

Источник: артефакт «NR_Point Home», 5 досок (Main, Notifications, LevelSheet, PointsSheet, LevelUp). Макет перечитан заново, не по памяти.

### Что перенесено

- Шапка: логотип, приветствие, колокольчик с точкой и всплывающим списком (свайп «Прочитано», «Прочитать все»), меню «⋮». Файлы: `home-topbar.tsx`, `home-notes.ts`.
- Карточка уровня со счётчиком процентов и шкалой, плитки XP и баллов, «Свободные задачи», строка «XP за месяц». `home.tsx`, `home.css`.
- Листы «Уровень» и «Баллы» (шторки снизу, Esc, возврат фокуса, системная кнопка «назад» Telegram). `home-sheets.tsx`.
- Экран «Новый уровень»: кольца, конфетти, счёт XP, шкала до следующего. `home-level-up.tsx`.
- Анимации макета (появление, счётчики на `@property`, бегущий блик шкалы, парение, отскок) с отключением при `prefers-reduced-motion`; шрифты Unbounded, Sora, Manrope лежат в репозитории (SIL OFL), внешних запросов нет.
- Палитра макета действует только на «Главной» (`html[data-view="home"]`), остальные экраны не затронуты.

### Что отличается от макета (и почему)

1. **Уведомления.** Серверной ленты нет. Список собирается из уже существующих данных: начисления за принятые задачи, новые назначения, решения по заявкам; окно 7 дней, не больше 8. Пометка «прочитано» хранится только на устройстве.
2. **Меню «⋮».** Только «Профиль» и «Помощь»: пунктов «Настройки» и «Выйти» в сервисе нет.
3. **Лист «Уровень».** Нет третьей ступени (порога уровня N+2 нет в API). Утверждение макета «уровень влияет на рейтинг» заменено на «рейтинг считается по XP за месяц» (так в плане).
4. **«Примерно N задач».** Считается по наибольшему фонду XP свободной задачи; если свободных задач нет, показывается общий текст.
5. **Лист «Баллы».** Награды берутся из реального каталога; названия в макете — примеры.
6. **Убрано** «Ближайший срок» и «Ещё в работе»: по решению пользователя («зачем эта табличка…»). Карточка «Очередь проверки» (только при праве на проверку) и подсказка «Как это работает» (при 0 XP) сохранены.
7. **Строка «XP за месяц»** показывается только при включённом рейтинге.
8. **Экран «Новый уровень»** показывается при росте уровня относительно последнего показанного на этом устройстве (на первом запуске не показывается). На реальном повышении уровня не проверялся.
9. Числа без разделителей тысяч (как в макете); вёрстка тянется по ширине вместо фиксированных 390×844; цвета Telegram-темы не используются.
