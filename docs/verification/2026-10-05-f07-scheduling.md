# F07: проверка отложенной публикации условий

Дата: 05.10.2026. Основание: IMPLEMENTATION_PLAN.md §§ 5–7, 10–12 (F02/F06/F07), [контракт](../implementation/2026-10-05-f07-scheduling-slice.md), [ADR-0021](../adr/0021-synthetic-catalog-scheduling.md). Это локальный синтетический срез, не приёмка F07/R1 или внешний выпуск.

## Подтверждено кодом

- `db/migrations/000029_catalog_scheduling.js`: только новое allowlisted действие `admin.catalog.schedule`, без выдачи полномочий или новых таблиц/ACL. Немедленная публикация требует своего прежнего права.
- `packages/contracts/src/catalog-publication.ts`, `admin-catalog.ts`, `index.ts`: отдельный strict scheduling body с UTC effectiveFrom и миллисекундами; canSchedule по умолчанию false. Немедленный контракт дату отклоняет.
- `packages/domain/src/admin/publish.ts`: общая транзакция/identity-quota barrier и повторная authority, отдельные action/operation/hash. Future date после ожиданий и при INSERT; immutable versions/publications/reason/replay. Старые квоты, баланс и снимки заявок не переписываются. Replay после effectiveFrom возвращает первоначальную запись, при отозванных правах отказывается.
- `apps/app/src/app/api/v1/admin/rewards/[id]/scheduled-versions/route.ts`, `shared/server/catalog-publication.ts`: Node Route Handler, no-store, Origin/CSRF/session, bounded strict body/query/headers и общий actor limiter. Отдельный default-false scheduling flag плюс read flag. canSchedule — UI affordance, не источник полномочий.
- `apps/app/src/features/catalog-admin/catalog-publish.tsx`, `catalog-admin.tsx`: самостоятельная кнопка, UTC datetime и preview МСК, unavailable cancellation, один dirty/Back guard, unknown retry с неизменным intent. Дата без native seconds нормализуется в UTC с `.000Z`. При 404 отменяются все три группы protected queries перед очисткой кэша.
- `tests/integration/catalog-publication.test.ts`, `tests/browser/catalog-scheduling.mjs`, `tests/integration/database-restore.test.ts`: отрицательные HTTP, реальные PostgreSQL locks/races, browser-to-DB, UI states, restore future terms/replay. Новый `--catalog-scheduling-only` runner включён также в полный и admin-catalog прогон.

## Независимые ожидания и сценарии

Проверены первоначальные version=1/price=30 и будущие version=2/price=19; current до effectiveFrom остаётся 1, scheduled показывает 2. Server updatedAt раньше intended effectiveFrom, saved UTC date совпадает с запросом. Квота capacity=9/reserved=0/used=0 и баланс не меняются при schedule. После сохранения резерва прежние price=30/version=1/conditions остаются, reserved=1; после наступления серверной даты reader выбирает version=2/price=19, старый reserve payload отклоняется conflict. Replay остаётся первоначальным, publications ровно 1.

Past date, stale version, вторая future версия, чужая область, выключенный flag, read-only/publish-only authority и отсутствие CSRF/Origin отклоняются. Scheduling-only authority не даёт immediate publish. Изменение даты под тем же ключом — idempotency conflict. Schedule/schedule и schedule/immediate race оставляют одну запись. Удержание quota lock до наступления даты отклоняет schedule и удаляет незавершённый intent; истечение session/permission после ожидания также отклоняет запись. HTTP действительно обращается к Next.js и PostgreSQL от impuls_app; browser-to-DB сохраняет version=3 с указанной датой и неизменной квотой, без API mocks. В нём подменяется только внешний Telegram bridge script для детерминированной загрузки, не Telegram/WebView.

Отдельные browser fixtures синтетически подменяют API для UI loading/pending, disabled/future, retry 0/429/503, 409/422, 401/403/404, dirty/Back, scope switch/late mutation response, datetime mismatch, native validation/keyboard и enlarged text. Снимки form/preview на 320/360/390/1280 px имеют document top, без horizontal overflow и pageerror. Форма и preview просмотрены отдельно; [mobile form](assets/f07-scheduling/catalog-scheduling/form-320.png), [desktop preview](assets/f07-scheduling/catalog-scheduling/preview-1280.png), [large text](assets/f07-scheduling/catalog-scheduling/text-scale-320.png). Мок-сценарии не приравниваются к DB доказательству.

## Сбои и исправления

Необработанная 000003 при попытке обычного migrate откатилась из-за уже существующей cluster role; временный runner применил штатный подход restore с provisioned role. Первый restore без PG_BIN отказал; повтор с установленным клиентом прошёл. После добавления второго publication fixture независимый restore count изменён с 1 на 2 и проверен повторно.

Новые test fixtures выявили автоматически отозванную сессию после правки permission, timeout браузера и ошибочный Date API вызов для JSON-строки; fixtures исправлены (session renewal, bounded native browser waits и string-to-Date). Реальный браузер обнаружил label, куда попадал поясняющий текст: пояснение вынесено из label в отдельный aria-describedby paragraph. Native datetime fill с `:00` заменён minute representation; negative decimal fixture сначала заполняет required дату, чтобы проверить именно Zod rejection. Unit default capability expectation дополнен canSchedule=false. Неудачные попытки не объявляются успешными.

Независимый Impeccable finish review нашёл pending protected-history/quota reads при 404 mutation denial; handler теперь явно отменяет все три query groups перед очисткой. Новый сценарий открывает обе истории с задержанными ответами, наблюдает два cancelled requests, затем выпускает поздние ответы и проверяет отсутствие rows/pageerrors. Финальный runner exit 0: 22 tests и 20 browser scenarios; [сохранённый лог](assets/f07-scheduling/verification.log). Reviewer verdict: **resolved**, disposition **ship только для перечисленного исправления**, не whole-surface/F07/R1 approval. [UI review](2026-10-05-f07-scheduling-ui-review.md), [design documentation](2026-10-05-f07-scheduling-design-documentation.md). Frontmatter/sidecar сохранены; прежний R0/runtime drift явно описан documenter и не ремонтировался.

## Ограничения и решения владельца

Новых зависимостей нет; bun.lock, runtime, transport и архитектурные границы не менялись. Проверены [официальные PostgreSQL 17 правила блокировок](https://www.postgresql.org/docs/17/explicit-locking.html) и [Supabase роли](https://supabase.com/docs/guides/database/postgres/roles); changelog.md через web tool не прочитан из-за unsupported content-type. Новый Supabase SDK/CLI/API не используется; это существующие pg транзакции. Target PostgreSQL 17.6/remote CI, внешние миграции/hosting, физический Telegram Android/iOS, OS scaling, screen reader, нагрузка и полный security scan не выполнены этим срезом. Показанные synthetic technical limits не утверждают P-решения.

Migration/API/UI выпускаются совместно, сначала 000029. Flags false по умолчанию. Остановка новых scheduling writes не отменяет уже сохранённую future дату; отмена/замена будущих условий и правка/отмена квот требуют отдельных контрактов. P-01…P-06, реальная экономика/полномочия, Bot API и hosting worker, target Linux и полная приёмка F07/R1 остаются открытыми.
