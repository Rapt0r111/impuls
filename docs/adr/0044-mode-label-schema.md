# ADR-0044: метка mode уходит из схемы БД в два шага (миграции 000051 и 000052)

Статус: принято, 26.10.2026 (второй шаг ADR-0029, этап 2). Миграция 000051 применена на Production (impuls-release) вручную 26.10.2026; 000052 ждёт слова владельца.

## Контекст

Новые записи должны писаться без `mode = 'synthetic'`, а старый код ещё пишет метку. Поэтому схема сначала разрешается для обоих вариантов, потом код переключается, потом столбцы уйдут (следующая миграция).

## Решение

- 000051: снимает семь CHECK с `synthetic`, делает `mode` необязательным в шести таблицах, пересоздаёт три политики и индекс `redemptions_due_idx` без предиката по метке и двенадцать функций. Сравнения `mode` стали `IS NOT DISTINCT FROM`, поэтому связи старой и новой записи не теряются. Данные не менялись.
- 000052: остались две политики вставки службы истечения (`ledger_expiry_service_insert`, `outbox_expiry_service`) с проверкой `mode = 'synthetic'`. Теперь они проверяют только вид записи. `expire_one_synthetic_reservation` переносит `mode` из резерва (`d.mode`). `enqueue_task_due_reminders` пока пишет `'synthetic'`: старый воркер берёт из очереди только такие записи, функция сменится вместе с удалением столбцов.
- `expire_one_synthetic_reservation` и `read_synthetic_expiry_status` принадлежат роли `impuls_expiry_executor`. Их пересоздание идёт под этой ролью с временной выдачей `SET` и `CREATE` в схеме, как в 000027 и 000028; иначе в Supabase выходит `42501: must be owner of function`.

## Последствия

- Старый код продолжает работать после обеих миграций: он пишет `'synthetic'`, функции переносят это значение.
- Новый код (следующий PR) пишет пустой `mode`. Воркер без фильтра по метке нужно развернуть до приложения или вместе с ним, иначе записи без метки в очереди не заберёт старая версия воркера.
- Откат 000052 возвращает политики; функции прежними не восстанавливаются.

## Проверки

- `tests/integration/synthetic-mode-schema.test.ts`: нет CHECK с `synthetic`, `mode` необязателен, пять политик не упоминают `mode`, функция истечения не пишет литерал.
- Полный прогон `bun run ci:local` на PostgreSQL 17.10: см. описание PR.
