# ADR-0036: настройки начислений без «версий» в интерфейсе

- Статус: принято локально
- Дата: 12.10.2026
- Авторы и утверждающие: исполнитель по просьбе владельца 12.10.2026 («полностью переработать механизм правил: сделать их ясными или удалить, если не нужны»); владелец выбрал вариант «Упростить» на карточке решения в треде.

## Контекст и причина

ADR-0035 дал экран «Правила начислений» с двухшаговой «публикацией версий». Владелец спросил, для чего нужны версии, и попросил сделать механизм понятным либо убрать. Версии в интерфейсе были видны в десяти местах: выбор версии при постановке задачи, строка «Версия правил» в задаче и в очереди проверки, «правила N» в истории задачи, журнале и профиле, подтверждения постановки.

Что настройки реально определяют (подтверждено кодом `packages/domain/src/admin/rules.ts`, `tasks/reviews.ts`, `profile/read.ts`): часовой пояс месяца, включено ли начисление при приёмке, нижний предел награды, бонусы проверяющего и пороги уровней. Удалить их нельзя без потери решения P-04 (снижение до 50 % и бонусы) и уровней, а любая правка вернулась бы миграциями.

## Решение

- **Хранение не меняется.** Каждое сохранение настроек по-прежнему создаёт неизменяемую запись `impuls.rule_sets` и строку `rule_publications`. Задача хранит запись, действовавшую при создании, поэтому смена настроек не меняет назначенное и начисленное (§ 5 плана). Миграций нет, контракты API не менялись.
- **Интерфейс говорит о настройках, а не о версиях.** Экран «Настройки начислений» (в «Ещё», группа «Для командира»): поля сгруппированы по смыслу (проверка отчёта, бонусы, уровни, месяц), у каждой группы одна фраза о том, что она значит. «Проверить изменения» показывает только то, что меняется («было → станет»), «Сохранить» отправляет. Если ничего не изменено, запрос не отправляется. Журнал называется «Кто и когда менял» и показывает дату, автора и пояснение без номеров.
- **Постановка задачи.** Выбор версии убран: форма всегда берёт действующую запись (`ruleSets[0]`, список отдаётся по убыванию номера). Раньше можно было выбрать устаревшую версию; теперь это невозможно из интерфейса.
- **Номера версий убраны** из задачи, очереди проверки, истории задачи, журнала, исправлений и профиля. Они остаются в базе, журнале действий (`ruleVersion`) и записях журнала начислений.
- Сообщения API об ошибках начисления говорят «настройки начислений».

## Последствия

- Для участников и командира понятие «версия правил» исчезает. Пояснение, по каким настройкам считалась конкретная задача, остаётся в базе и журнале действий.
- Пороги уровней по-прежнему применяются сразу ко всем; доли и бонусы — к задачам, созданным после сохранения.
- Не решено владельцем: отдельное право на бонус и общий предел бонусов (как в ADR-0035).
