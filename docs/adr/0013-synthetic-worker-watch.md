# ADR-0013: постоянный режим worker симуляции

Дата: 04.10.2026. Статус: локальное техническое решение, режим ожидания P-01…P-06. Продолжает [ADR-0012](0012-synthetic-notification-worker.md).

## Причина и решение

F08 и § 8 плана требуют независимой обработки сохранённого outbox и восстановления после сбоя. Ограниченный `--once` не замечает события, появившиеся после завершения запуска. Добавляем явный `--watch` для постоянного Node.js процесса; размещение и внешний supervisor этим не создаются.

Процесс работает последовательно, до 20 попыток в одном пакете, затем делает паузу даже при непустой очереди. `WORKER_POLL_INTERVAL_MS` — целое число 1000–60000, default 5000. Это начальный технический предел, не SLA или замер производительности. Пустая очередь не порождает повторяющиеся логи. Вывод содержит только simulation label, watching/stopped, агрегаты пакета и фиксированные коды ошибок.

SIGINT/SIGTERM прекращают новые захваты и прерывают паузу. Уже начатый claim завершается; если он получил событие, process завершает его исходной доменной операцией. Бизнес-транзакция не отменяется новым сигналом. Пул закрывается после drain; повторные сигналы не сбрасывают срок. Защитный срок 20 секунд включает drain и закрытие пула. По истечении процесс завершается с exit 1 / WORKER_STOP_TIMEOUT; исходный 30-секундный lease позволяет восстановление. Отмена отправленного сообщения и exactly-once внешняя доставка не обещаются.

Ошибка БД или idle pool приводит к exit 1 с нейтральным WORKER_UNAVAILABLE. Внутреннего бесконечного reconnect нет; будущий внешний supervisor должен применять backoff к рестартам. Принудительное завершение процесса не переводит outbox в sent и не переоткрывает терминальную simulation row. До истечения lease другой процесс не захватывает событие; после истечения действует прежний механизм пяти попыток с новым token.

Флаг проверяется при запуске и остаётся false по умолчанию. Изменение окружения не меняет уже работающий процесс: для выключения требуется stop, затем запуск с false. Зависимости, runtime Node.js, Bun build, private схема 000001–000021, права worker, TLS и тестовый транспорт сохраняются. Ни API, ни UI, ни обработчик автоматического истечения F06 не меняются.

## Проверка и ограничения

Переход: остановить прежний worker, собрать ESM существующей командой Bun и явно запустить Node с `--watch` и отдельным окружением. Новая миграция/выдача прав не нужны. Откат: остановить watch и продолжить прежние ограниченные `--once`/`--status` на той же схеме; сохранённые simulation rows и leases не удалять. Перезапуск ждёт прежний срок lease и не обнуляет attempts.

Публичные границы проверки: Node CLI + сохранённые инварианты изолированной PostgreSQL; управление жизненным циклом через AbortSignal. Проверяем новые события после idle, пакетный предел и паузу, drain, crash/restart/lease, отказ соединения и disabled/invalid config. На Windows `child.kill('SIGTERM')` принудительно завершает процесс и не проверяет graceful handler; отдельный POSIX-тест предназначен для Linux CI. Его локальное исполнение не заявляется. Защитное принудительное завершение через 20 секунд требует отдельной проверки зависшего процесса на целевом хосте.

Первичные источники: [Node.js 24 signal events](https://nodejs.org/docs/latest-v24.x/api/process.html#signal-events), [таймеры Node.js](https://nodejs.org/api/timers.html#timers-promises-api), [соединения Supabase для persistent backend](https://supabase.com/docs/guides/database/connecting-to-postgres). Будущий supervisor запускает непосредственно `node apps/worker/dist/index.mjs --watch`, чтобы передавать сигнал самому Node, а не оболочке команды Bun.
