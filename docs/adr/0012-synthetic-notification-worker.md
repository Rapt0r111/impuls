# ADR-0012: отдельный worker симуляции уведомлений

Дата: 04.10.2026. Статус: локальное техническое решение в режиме ожидания P-01…P-06.

§ 8 плана и F08 требуют независимой обработки outbox, нейтрального текста, повторов и прекращения уведомлений после отзыва доступа. Существующие операции уже сохраняют события; `apps/worker/src/index.ts` был placeholder. Реальные получатели, разрешённый контур и запуск пилота не утверждены. Разработку механизма продолжаем на синтетических данных, без отправки Bot API.

Миграция 000021 вводит отдельную `notification_simulations`: один результат на outbox ID, состояния ready/processing/retry/simulated/failed/suppressed, пять попыток, 30-секундный lease и UUID token. SKIP LOCKED разделяет конкурентных обработчиков; просроченный token не записывает результат. Backoff после ошибок — 30/60/120/240 секунд; после пятого сбоя — failed. Пятая прерванная попытка также завершается failed после lease. Терминальные записи не переоткрываются; rollback миграции запрещён для сохранения свидетельств. Исходные события, их attempts/status/version и бизнес-операции не меняются. `simulated` не означает доставку.

`impuls_worker` — отдельная NOLOGIN/NOBYPASSRLS роль. Она читает только необходимые столбцы synthetic outbox и пишет simulation queue. У неё нет доступа к Telegram ID, текстам, сессиям, балансовым операциям или выдаче полномочий. Runtime login и членство в этой роли не создаются; это будущая отдельная эксплуатационная процедура. Приложение не получает доступ к simulation table.

Узкое исключение SECURITY DEFINER — private `lock_notification_recipient(uuid)` с фиксированным `search_path=pg_catalog`, полным именем таблицы, результатом boolean, отозванным PUBLIC EXECUTE и правом вызова только worker. Оно удерживает FOR SHARE до окончания транзакции, не давая worker изменять users. Эта граница нужна для сериализации с отзывом active; стандартный auth.uid Supabase здесь неприменим, используется собственная серверная модель доступа. Guard таблицы SECURITY INVOKER. Lease повторно проверяется после ожидания доступа и при сохранении результата.

Node.js 24 остаётся runtime. Bun собирает только worker и доменный модуль в ESM, pg остаётся внешним существующим пакетом. Прежний tsc build placeholder заменён Bun build; строгая проверка TS остаётся отдельной командой. Фреймворк, PostgreSQL, HTTP, менеджер пакетов и зависимости не меняются. Worker не загружает приложение `.env.local` или bot token; его отдельное окружение содержит off-by-default flag, WORKER_DATABASE_URL и при удалённом соединении проверяемый CA. Запуск принимает только `--once` (не более 20 обработок) или `--status` (счётчики без идентификаторов/текстов). Scheduler и размещение не добавлены.

Транспорт принимает только тестовую квитанцию `simulated`; встроенный sink не выполняет сеть. Таймаут 5 секунд и AbortSignal ограничивают ожидание; исключения превращаются в allowlisted code. Повторная симуляция после сбоя записи возможна: exactly-once внешней доставки не заявляется. Bot API не обеспечивает общую транзакцию с PostgreSQL; будущий адаптер обязан отдельно описать неоднозначный результат, повтор, HTTP 429/403, rate limits, consent и реальные адреса. Для автоматического истечения резерва нужен отдельный доменный контракт: уведомления не меняют статус заявки.

Срез не закрывает F08/R1: нет реальной отправки, admin UI неотправленных событий, напоминаний, сезонных событий, supervisor/scheduler, удалённого выпуска или проверки устройств. Проверки и ограничения: [отчёт](../verification/2026-10-04-f08-simulation-worker.md).
