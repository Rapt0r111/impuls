# ADR-0046: проверяющий обычной задачи

Статус: принято, 26.10.2026. Миграция `000054_verifier_recommendations`: одна новая таблица, остальное переиспользует существующее.

## Контекст

Командир выдаёт обычную задачу участнику (`task.create`, `task.assign`), но выбрать проверяющего для неё нельзя: проверяющие с ADR-0045 есть только у самостоятельных задач. Принимать и начислять баллы и XP по-прежнему может только командир (`task.review`, ADR-0041, ADR-0042). Владелец решил, что проверяющий задачи может вернуть отчёт на доработку и рекомендовать ХП и баллы, но не принимать его.

## Решение

- Выдача задачи (`assignTask`, `POST /api/v1/tasks/[id]/assign`) принимает необязательный `verifierId`. Проверяющим может быть активный пользователь с `task.verify` в области, не исполнитель задачи; строка пишется в существующую `task_verifiers`. Иначе `verifier_invalid` (422, `TASK_VERIFIER_INVALID`). Задача отдаёт `verifier`, список `verifiers` есть в вариантах области.
- Проверяющий обычной задачи (строка `task_verifiers` и `task.verify`) может:
  - вернуть отчёт на доработку тем же `reviewTaskSubmission` / `returnTaskSubmission`; право проверки расширено: `task.review` или выбранный проверяющий, только для `return`;
  - рекомендовать ХП и баллы за отчёт: `recommendTaskSubmission`, `POST /api/v1/submissions/[id]/recommend`. Запись одна на отчёт (`verifier_recommendations`), можно изменить, пока отчёт ждёт проверки. Статус и версия задачи не меняются.
- Принимать (`accept`) и начислять может только `task.review`. У проверяющего в очереди `acceptance.enabled = false`, поэтому его форма показывает только «Вернуть» и «Рекомендовать»; сервер проверяет это сам.
- Очередь (`GET /api/v1/reviews`) пускает и проверяющих; раздел проверки виден при `task.review` или `task.verify`. Командир видит рекомендацию в элементе очереди и получает её значения предзаполненными в форме приёмки; значения можно поменять, как и раньше, по правилам начислений.

## Последствия

- Проверяющий не принимает отчёт, не ставит баллы в начислении и не меняет фонд; рекомендация только подсказывает командиру.
- Самостоятельные задачи (ADR-0045) не меняются: там проверяющий уже принимает решение «передать с баллами».
- Новых прав нет.

## Миграция и откат

- `000054_verifier_recommendations`: таблица `impuls.verifier_recommendations` (submission_id PK, verifier_id, recommended_xp, recommended_points 0..100000), права `impuls_app` на SELECT, INSERT, UPDATE, RLS-политика как у `task_verifiers`.
- Порядок: сначала применить `release/apply-000054.sql` в SQL Editor, затем сливать PR (Vercel деплоит main сразу). Без таблицы эндпоинт рекомендаций вернёт ошибку БД, остальное работает.
- Откат: `DROP TABLE impuls.verifier_recommendations` и откат кода. Строки `task_verifiers` для обычных задач остаются и безвредны, так как проверка идёт по статусу `in_review`.
