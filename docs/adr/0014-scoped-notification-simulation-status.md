# ADR-0014: сводка состояния симуляции в точной области

Дата: 04.10.2026. Статус: принято для локального синтетического среза F08/F07.

## Основание

План §§ 8, 10–12 требует наблюдать неотправленные события без служебного текста. ADR-0012/0013 дают private receipts и CLI worker; приложение пока не читает их. Общий `admin.audit` не должен автоматически давать доступ к состоянию обработки.

## Решение

- Отдельное точное `admin.notifications`, без автоматической выдачи полномочий. Миграция 000022 расширяет allowlist действий и даёт `impuls_app` только SELECT(outbox_id,status,error_code) с private SELECT policy; worker ACL сохраняются. Токен/срок lease и запись не доступны приложению.
- No-store GET `/api/v1/admin/notifications?scope=<uuid>` и доменный reader. Сессия, active, срок/отзыв полномочия и сводка читаются одним PostgreSQL statement. Scope определяется сохранённой задачей через assignment/review/correction либо сохранённой заявкой; членство текущего получателя не определяет область.
- Ответ содержит только mode=simulation, разрешённые scope names/IDs, server updatedAt, семь счётчиков и пять allowlisted причин. Только synthetic pending исходные события; отсутствие receipt отдельно обозначено `unclaimed`. Причины — последняя сохранённая причина одного события, не сумма попыток. `processing` может включать истёкший lease до восстановления worker.
- Просмотр выключен по умолчанию отдельным `SYNTHETIC_NOTIFICATION_STATUS_ENABLED`; включение не запускает worker и не означает Bot API доставку. Сохранённую историю можно читать при остановленном worker.
- Расширение существующего рабочего интерфейса: ручное обновление, точная область, плоские счётчики, раскрываемые причины. 503/offline сохраняют подтверждённую сводку и её время; 401/403/404 очищают кэш сводок. При четырёх рабочих направлениях навигация использует два столбца.

## Последствия и границы

Схема private; новых функций SECURITY DEFINER, Data API грантов, зависимостей, отправки/повторов из UI и финансовых изменений нет. Это сводка, а не список событий, heartbeat процесса, журнал попыток или доказательство доставки. Детализация отдельных событий и реальный транспорт требуют следующего контракта. P-01…P-06, удалённый выпуск, supervisor, восстановление и Telegram Android/iOS остаются открытыми.

## Миграция и проверка

Для последующего выпуска сначала 000022, затем совместный API/UI; flag остаётся false до отдельного решения. При откате приложения receipt history не удаляется. Down допускается только без bindings `admin.notifications`, не меняет receipts/outbox; при существующем праве откат отклоняется атомарно.

Проверки: миграция up/down/grants, точные/соседние области, срок/отзыв доступа, все состояния и независимые ожидаемые значения, provenance всех типов источника, отсутствие изменения бизнес-записей, реальный HTTP/browser-to-DB и UI 320/360/390/1280.
