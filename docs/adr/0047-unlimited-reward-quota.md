# ADR-0047: поощрение без лимита мест

Статус: принято, 27.10.2026. Миграция `000055_unlimited_quota_capacity`: снимает NOT NULL у `capacity` и разрешает NULL.

## Контекст

Квота поощрения (`impuls.quota_periods`, ADR-0016/0017) всегда имеет число мест. Заявка резервирует место в периоде, и при `reserved + used >= capacity` сервер отвечает `quota_full`. Владелец попросил возможность выбирать лимит или безлимит при создании поощрения и публикации периода.

## Решение

- `capacity IS NULL` означает «без лимита». Число мест по-прежнему от 0 до 1 000 000.
- Заявка без лимита не проверяет места: `mutateRedemption` пропускает `quota_full`, но всё остальное (период, баланс, право, идемпотентность, блокировки) остаётся. Счётчики `reserved` и `used` ведутся как прежде.
- Ответы API и чтение каталога отдают `capacity: null` и `available: null` для безлимита. Раньше отдавали числа. Пары согласованы контрактом: `capacity === null` тогда и только тогда, когда `available === null`.
- Форма создания поощрения и публикации периода получают флажок «Без лимита», который отключает поле мест.
- Таблица `quota_publications` (история публикаций) тоже допускает NULL, снимок остаётся неизменяемым.
- Новых прав, флагов и таблиц нет.

## Последствия

- Ограничение безлимита только по строке квоты: отдельной «бесконечной» квоты нет, безлимит ставится на период.
- Существующие периоды с числом мест не меняются.
- Пока каталог выключен флагами Vercel, участники эффект не видят.

## Миграция и откат

- `000055_unlimited_quota_capacity`: `quota_periods.capacity` и `quota_publications.capacity` допускают NULL; проверки `quota_periods_capacity_check`, `quota_periods_occupancy_check` (reserved + used <= capacity, если capacity задан) и `quota_publications_capacity_check` переписаны; проверка `ends_at > starts_at` не меняется.
- Порядок: сначала применить `release/apply-000055-unlimited-quota.sql` в SQL Editor, затем сливать PR. Старый код с NULL в ответе не разберёт, поэтому безлимит появится только после слияния.
- Откат: миграция необратима без потери данных (NULL нельзя вернуть в число). Откатывается код, а уже созданные безлимитные периоды остаются на сервере и требуют отдельного решения владельца.

## Проверки

- `tests/integration/unlimited-quota.test.ts`: безлимит принимает все заявки, счётный период по-прежнему отказывает при заполнении, отрицательное число мест отклоняется базой.
- `packages/contracts/src/unlimited-quota.test.ts`: пары `capacity`/`available` и границы запроса публикации.
- Существующие `quota-publication`, `rewards`, `catalog-cancellation` и остальные интеграционные тесты на PostgreSQL 16 дают тот же набор падений, что и `main` (окружение: CLI worker без сборки, коллации, роль PG 17 в CI).
- Не проверено на Production и на устройстве: миграция и формы проверены только на локальной базе PostgreSQL 16.
