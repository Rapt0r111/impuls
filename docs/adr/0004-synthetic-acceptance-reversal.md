# ADR-0004: полный синтетический возврат начисления

Дата: 02.10.2026. Статус: принято для локального синтетического среза F04. Пользователь выбрал полный возврат первым сценарием; это не утверждение реальных правил P-04.

## Причина

План §§ 4–6, F04 § 11 требует компенсации ошибочного начисления, append-only журнала и неотрицательного доступного остатка. Приёмка уже сохраняет две исходные валютные записи. Произвольные корректировки/бонусы и служебный спорный порядок ещё не определены.

## Решение

Первый срез возвращает весь сохранённый фонд одной синтетической приёмки ровно один раз. Независимое `ledger.correct` в точной области и отдельный выключенный по умолчанию флаг защищают операцию. Самокорректировка запрещена. Идентификатор исходной приёмки, причина, версия баланса получателя и UUID намерения обязательны. `task.review`, `task.view` и `admin.*` не заменяют это право.

Неизменяемое решение связывает две отрицательные записи с исходными строками; PostgreSQL проверяет точное отрицание, валюту, получателя, правила и исходный сезон. Приёмка, отчёты, задача и прежние записи не переписываются. Решение, записи, проекция, audit, нейтральный outbox и идемпотентный ответ коммитятся вместе. При нехватке XP/доступных баллов — отказ, без расходования резерва, долга и частичного возврата.

Порядок блокировок согласован с review/revocation: пользователи → права → сессия → задача → баланс → ключ намерения. Сроки доступа повторно проверяются после ожиданий. Параллельное начисление или компенсация другого результата меняет версию общего баланса; оператор перечитывает и явно подтверждает новые суммы. Повтор неизвестного результата сохраняет исходное тело/ключ и проверяет текущий доступ прежде сохранённого ответа.

## Последствия и границы

Миграция 000014 расширяет журнал знаковыми суммами и добавляет связи коррекции audit/outbox. Runtime получает только SELECT/INSERT новой истории. Старые клиенты, ожидающие только положительные суммы, нельзя выпускать вместе с новым сервером: нужен согласованный выпуск миграции, API и UI. При наличии коррекций down отказывается удалять историю; откатывается приложение при сохранении схемы.

Коррекция сохраняет исходный месяц и меняет lifetime XP, не создавая XP месяца исправления. F05/F12 должен суммировать компенсации и отдельно реализовать `season_errata` для будущих опубликованных снимков/кубков. Снимков сезонов сейчас нет; их закрытие и пересмотр здесь не реализованы. Индивидуальные бонусы, частичный возврат, повторная приёмка/переоткрытие, расходование и реальные спорные начисления остаются отдельными контрактами и P-04. Delivery worker F08 не реализован; наличие outbox не означает отправку.

Стек, runtime, транспорт и модульные границы не меняются, зависимости не добавляются. Контракт: `../implementation/2026-10-02-f04-corrections-slice.md`; проверка: `../verification/2026-10-02-f04-corrections.md`. PostgreSQL 17.6 CI и физический Telegram остаются отдельной проверкой.
