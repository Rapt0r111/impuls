# ADR-0003: условия черновика и отмена задачи

Дата: 02.10.2026. Статус: инженерная граница синтетического F03; не согласование P-решений.

## Контекст

F03 требует редактирования/отмены, но прежний runtime мог менять только статус и версию задачи. Назначение фиксирует обещанный исполнителю фонд и критерии; review начисляет сохранённый фонд. Произвольное изменение после начала работы создало бы неоднозначность условий принятого отчёта.

## Решение

`task.edit` и `task.cancel` — отдельные действия в точной области. Редактирование меняет семь полей условий только при `draft → draft`; правила и область не меняются. После назначения условия заморожены: PostgreSQL BEFORE UPDATE trigger сравнивает старое/новое состояние и поля, отклоняя изменение вне черновика (`23514`). Ограниченная роль получает UPDATE только нужных колонок. Проверка полномочий и synthetic-флага остаётся доменной, запросы идут через Route Handlers.

Отмена незакрытой задачи меняет статус/версию с причиной. Она не удаляет назначение/отчёт, не создаёт review, не начисляет и не компенсирует. Статус задачи исключает непроверенный отчёт из очереди. Приёмка и отмена используют одну строковую блокировку и expectedVersion; одна из конкурирующих операций отказывается с конфликтом.

Неизменяемое событие сохраняет причину и снимок условий. Старые события не дополняются предположениями. Полный request/response по ключу остаётся транзакционным; replay проходит текущий доступ. UI защищает несохранённый ввод и сохраняет тело/ключ при неизвестном результате.

## Последствия и альтернативы

Нельзя исправить назначенную задачу этим API: требуется новая задача. Расширение на изменение условий после назначения потребует отдельного решения о согласии исполнителя, версии отчёта и фонде, миграции и новых гонок. Нет новой зависимости, runtime, платформы или экономики. Корректировки принятого результата принадлежат F04; доставка уведомлений — F08.

## Миграция, проверки и откат

000013 зависит от 000012. Перед выпуском нужны 000011–000013 и согласованная остановка старых writers: прежний код не сохраняет снимок условий. Схема допускает старые события с null-снимком, но запуск старого кода после новых прав/событий функционально ограничен. Down отказывается при новых правах, аудите или снимках; сохраняйте историю, откатывая приложение. После использования заморозка условий не снимается ради отката.
