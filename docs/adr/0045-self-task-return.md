# ADR-0045: ответственный проверяющий возвращает свой отчёт на доработку

Статус: принято, 26.10.2026. Миграций нет.

## Контекст

Шесть проверяющих получают `task.verify`, но не `task.review`: приёмка с `task.review` фиксирует баллы и XP, а их решает только командир (ADR-0041, ADR-0042). Проверяющий, увидев недочёт в отчёте участника, мог лишь отклонить отчёт, то есть закрыть его без возможности исправить. Владелец потребовал, чтобы проверяющий возвращал на доработку только те задачи, где он назначен ответственным, и не получал для этого прав на баллы.

## Решение

- В `verifySelfTask` появилось решение `return` с обязательной причиной. Оно доступно только тому одному проверяющему, которого участник выбрал для этого отчёта (`task_verifiers`); любой другой проверяющий получает «не найдено».
- Возврат записывает `reviews` (decision `return`, без баллов и XP), событие `returned`, `audit_events` (`task.return`) и уведомление автору `task.returned`; статус задачи становится `needs_work`.
- Новая операция `resubmitSelfTask` доступна только автору отчёта: он правит текст, получает следующую попытку в `submissions`, статус снова `awaiting_verification`. Выбранный проверяющий должен ещё быть активным, с `task.verify` и в области, иначе `verifiers_invalid`.
- Эндпоинт `POST /api/v1/self-tasks/[id]/resubmit`; в интерфейсе «Вернуть на доработку» у проверяющего и «Отправить снова» у автора.
- Новое право и миграция не нужны. Обычные задачи командира возвращает по-прежнему только `task.review`, у проверяющих его нет.

## Последствия

- Проверяющий не может принять отчёт и зафиксировать баллы: решение командира об очках не затрагивается.
- Возврат не меняет фонд и не создаёт назначение.

## Проверки

- `tests/integration/self-tasks.test.ts`: чужой проверяющий и автор не могут вернуть; возврат создаёт событие и уведомление; повторная отправка даёт попытку 2 и снова ждёт проверяющего.
- `packages/contracts/src/self-tasks.test.ts`: решение `return` требует причину, `resubmit` требует текст.
