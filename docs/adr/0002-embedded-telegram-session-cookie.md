# ADR-0002: Cookie сессии во встроенном Telegram Web

- Статус: Telegram Web подтверждён скриншотом пользователя после Production-релиза; Android/iOS остаются непроверенными.
- Дата: 29.09.2026.

## Контекст

После успешного `POST /api/v1/auth/telegram` Production-логи показали `401` на следующем `GET /api/v1/me/permissions` (`docs/verification/2026-09-29-f02-foundation.md`). Скриншот пользователя показывает соответствующее состояние. Логи не содержат cookie, поэтому отсутствие cookie в запросе остаётся выводом из поведения, а не прямым наблюдением.

Mini App может открываться во встроенном окне Telegram Web. При таком запуске сайт приложения находится в стороннем iframe. `SameSite=Lax` не отправляет cookie из iframe в `fetch`, что объясняет наблюдаемую последовательность. [MDN: Third-party cookies](https://developer.mozilla.org/en-US/docs/Web/Privacy/Guides/Third-party_cookies), [MDN: Set-Cookie](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie).

## Решение

Сервер задаёт cookie сессии с `HttpOnly; Secure; SameSite=None; Partitioned; Path=/`. Атрибут `Partitioned` отделяет cookie по верхнему сайту; `SameSite=None` разрешает её передачу в iframe. Вход и выход используют одинаковые атрибуты, чтобы выход удалял cookie из того же раздела. Токен остаётся случайным 256-битным значением, в БД хранится только его SHA-256. Raw `initData` не сохраняется на клиенте.

## Последствия и безопасность

`SameSite=None` убирает защиту `Lax` от отправки cookie в стороннем контексте. Все изменяющие API-запросы обязаны проверять `Origin` и отдельный CSRF-токен; текущий `POST /auth/logout` делает обе проверки. Новые мутации проходят ту же проверку до выпуска. Cookie с `Partitioned` будет отдельной при запуске через разные верхние сайты; повторный вход там допустим. Браузеры, которые блокируют cookie во встроенном окне и не поддерживают этот атрибут, могут требовать другого транспорта сессии по отдельному ADR. Открывать реальные данные до P-01/P-02 и мобильной проверки нельзя.

## Миграция и откат

Миграция БД и новые зависимости не нужны. Уже открытое окно повторяет Telegram-вход и получает новую cookie. При откате к `SameSite=Lax` вход во встроенном Telegram Web снова может завершиться `401`; перед таким откатом нужен проверенный альтернативный транспорт сессии.

## Проверка

Браузерный тест `tests/browser/access-smoke.mjs` моделирует сторонний iframe: `SameSite=Lax` приводит к ошибке сессии, а `SameSite=None; Partitioned` позволяет запросу передать cookie. `bun run check` прошёл. После Production-релиза пользователь прислал скриншот Telegram Web с экраном «Доступ подтверждён» и тестовым участником; это подтверждает вход в данном Web-клиенте. Android/iOS WebView остаются непроверенными. Полный журнал проверки — `docs/verification/2026-09-29-embedded-telegram-login.md`.
