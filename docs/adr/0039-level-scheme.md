# ADR-0039: уровни без потолка, названия настраиваются в правилах

Статус: принято для черновой ветки, 14.10.2026. Пороги на Production не вводятся и миграция не нужна: пороги и названия живут в версии правил (`definition.progression`, ADR-0035).

## Контекст

Владелец ответил на предложение уровней: потолка нет, названия должны меняться в интерфейсе, уровень даёт только статус (без XP, баллов и прав). Раньше после последнего порога уровень становился «высшим», а названий не было.

## Решение

- После последнего настроенного порога каждый следующий уровень стоит столько же XP, сколько последний настроенный интервал. Пример: пороги 0, 150, 400, 800, 1500 дают уровень 6 с 2200 XP и уровень 7 с 2900 XP. Уровней без предела больше нет.
- `definition.progression.levelNames` — названия по порядку, с первого уровня; пустая строка означает «без названия». Названий не больше, чем уровней. Лимит 40 символов.
- Название показывается, если оно задано; иначе — «Уровень N». Профиль отдаёт `level.title` (`null`, если названия нет).
- Вычисление уровня по lifetime XP, правила выбора версии и поведение без порогов не меняются.
- Уровень ничего не даёт: ни XP, ни баллов, ни прав. Поощрения по уровням не вводятся.
- Праздничный экран «Новый уровень» показывается только при повышении относительно сохранённого на устройстве максимума: понижение из-за исправления XP не запускает его снова.

## Последствия

- Новые пороги меняют уровень всем участникам сразу по накопленному XP. Вводить пороги нужно один раз до приглашения участников; дальнейшие изменения — только с объявлением.
- Таблица порогов в интерфейсе по-прежнему до 100 строк, поэтому практически предел задают пороги, а не код.
- Контракт `level.level` больше не ограничен 100; `nextLevelXp` остаётся `null` только при одном уровне `[0]`.

## Проверки

- Юнит-тесты `progression.test.ts`: граница уровней, продолжение после таблицы, огромный XP, названия.
- Контракты `rules.test.ts`, `profile.test.ts`: названия не длиннее 40 символов и не больше уровней.
- Интеграционные тесты с PostgreSQL в этой среде не запускались; их нужно прогнать перед слиянием.
