# ADR-0011: явный срок и ручное истечение синтетического резерва

Дата: 04.10.2026. Статус: локальное техническое решение для синтетического режима.

План требует возврата просроченного резерва, но P-03/P-04 не задают реальный срок. Не выводим его из конца квоты и не назначаем значение по умолчанию. Добавляем nullable положительную длительность в неизменяемую версию условий и сохраняем рассчитанный сервером срок в заявке. Старые заявки сохраняют NULL.

Первый срез выполняет истечение вручную через существующее точное reward.decide с причиной и запретом собственного решения. Это расширение одного решения и его прежнего порядка блокировок; новый runtime, transport или полномочие не нужны. PostgreSQL и доменный сервис запрещают одобрение после срока. Возврат использует исходные цену, квоту, сезон и запись резерва, с уникальным разрешением и атомарным audit/outbox/replay.

Последствие: срок сам по себе не возвращает резерв; до ручного действия он удерживает ресурсы. UI сообщает об этом. F08 может позднее добавить автоматическую обработку в отдельном ADR с самостоятельным служебным доступом; пользовательская сессия не становится worker credential. Контрольные гонки и отрицательные проверки указаны в контракте среза. Никакие реальные сроки, служебные поощрения или пилот не утверждаются.
