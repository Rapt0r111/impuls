# ADR-0043: начисления по явному утверждению экономики в версии правил

Статус: принято, 26.10.2026 (первый шаг ADR-0029, этап 2). Миграций нет.

## Контекст

ADR-0029 убрал слово «синтетика» из интерфейса и флагов, но начисление XP и баллов всё ещё проверяло `definition.mode = "synthetic"` в версии правил (`syntheticEconomyZone`, `packages/domain/src/ledger/economy.ts`). Эта проверка защищает P-04: экономика пока не утверждена владельцем. Метка и защита совпадали по имени, поэтому снять метку без замены было нельзя.

## Решение

- Начисление (приёмка, исправление, выдача из очереди проверки) требует в сохранённой версии правил явное `economy.approved: true`. Версия без этого поля, включая первую, ничего не начисляет, даже при `ECONOMY_ENABLED=true`.
- Функция переименована в `economyZone`. Проверка `mode` из неё убрана; ключ `mode` пока записывается в новые версии и читается запросами, которые уберёт следующий шаг этапа 2.
- В форме «Настройки начислений» появилась галочка «Экономика утверждена владельцем». Её значение копируется в версию при публикации, поле `economy` предыдущей версии сохраняется.
- Версия, созданная миграцией 000039, поле не содержит. Чтобы начисления заработали, владелец публикует новую версию с галочкой.

## Последствия

- Флаги `ECONOMY_ENABLED` и `LEDGER_CORRECTIONS_ENABLED` не меняются и остаются выключенными.
- Поведение Production до публикации версии с галочкой не меняется: флаг выключен, а текущая версия без поля.
- Существующие строки журналов не переписываются.

## Проверки

- `packages/domain/src/ledger/economy.test.ts`: версия без поля, с нестрогим значением или без приёмки не начисляет.
- `tests/integration/rules-management.test.ts`: публикация сохраняет `economy.approved`.
- `tests/integration/rules-v2-migration.test.ts`: версия из миграции 000039 не даёт начислений до публикации владельца.
- Полный прогон `bun run ci:local` на PostgreSQL 17.10: см. описание PR.
