# F03: история отчётов и решений

Дата: 30.09.2026. Контракт среза до реализации, по IMPLEMENTATION_PLAN.md §§ 7, 11–12.

- Схема: существующие immutable submissions (000007), reviews (000008–000009), assignment и активная сессия. Новая таблица/миграция не нужна. История создания, назначения, начала, редактирования и отмены не входит в этот срез.
- GET `/api/v1/tasks/:id/history`: только исполнитель текущего назначения, без userId из клиента. Query: limit 1–50 (20 по умолчанию), cursor — положительный номер попытки до 2147483647. Ответ: taskId, items (id, attemptNumber, text, submittedAt, review либо null), nextCursor, asOf. Review содержит автора, причину, время, решение; accept — отдельные снимки XP/баллов, return — null для обоих фондов. Сам номер попытки задаёт порядок от новой к старой, независимо от времени/UUID.
- Домен проверяет активность пользователя, действующую сессию, назначение и видимый статус в одном SQL snapshot вместе со страницей. Нет сессии — 401; отзыв допуска — 403; чужой/несуществующий объект — одинаковый 404. Повторные/неизвестные query-параметры — 400. Все ответы private/no-store. Начисления/мутации отсутствуют.
- UI: раскрытие истории в существующей детали; плоские строки от новых к старым, текст отчёта, решение/основание/проверяющий и время, XP отдельно от баллов. Загрузка, пустота, ошибка/503/потеря сети с повтором и временем последнего чтения; 401/403 очищают доступ, 404 скрывает сохранённую историю. Пагинация/обновление не сбрасывают несданный текст. После сдачи отчёта история инвалидируется.
- Проверки: контракт (границы курсора и фондов); PostgreSQL под impuls_app (все попытки, пустая история, чужие назначения, деактивация/отзыв/expiry, страницы без повторов при новой попытке); реальные HTTP (auth, query, no-store); Playwright (пагинация, обновление, состояния/ошибки, сохранение формы, 320/360/390 px, клавиатура, reduced motion, длинный текст).

Режим синтетических данных сохраняется. Не внедряет P-решения, новые зависимости или ADR; F03/F04/R1 целиком не закрывает. Telegram Android/iOS, PostgreSQL 17 CI и внешний выпуск проверяются отдельно.
