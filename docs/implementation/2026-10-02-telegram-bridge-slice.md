# Telegram bridge: локальный срез контракта WebView

Основание: IMPLEMENTATION_PLAN.md § 7 и пробел № 4 в проверке состояния проекта от 02.10.2026. Срез обслуживает существующие экраны R1; серверные операции, экономика, права и схема БД не меняются. P-01…P-06 остаются открытыми. Это реализация адаптера и локальные проверки, не приёмка Telegram на Android/iOS и не завершение R1.

## Окружение

Единственный адаптер `shared/telegram/web-app.tsx` подключает окружение после обнаружения SDK. `environment.ts` читает `colorScheme`, `viewportHeight`, `viewportStableHeight`, `safeAreaInset`, `contentSafeAreaInset` и подписывается на `themeChanged`, `viewportChanged`, `safeAreaChanged`, `contentSafeAreaChanged`. Отсутствующие/отрицательные/нечисловые отступы и неположительная высота возвращают CSS fallback. Адаптер не читает `initDataUnsafe` и не получает полномочий из SDK.

Палитра приложения остаётся тёмной по § 7. `color-scheme: dark` сохраняет читаемость браузерных контролов. На подключении и `themeChanged` header/background/bottom bar получают существующий `--color-bg`; тема Telegram отражается в `data-telegram-theme`. Методы цвета независимы: отказ одного не блокирует остальные, ready/expand или вход. Новый светлый дизайн не вводится.

У каждой стороны CSS объединяет устройство и browser env через `max`, чтобы не учитывать один физический отступ дважды, затем прибавляет отдельный отступ контента Telegram. Это консервативная локальная политика, требующая проверки фактических значений в fullscreen на устройствах. Горизонтальные отступы тоже учитываются. Вертикальный минимум оболочки использует стабильную высоту, с fallback `100dvh`; промежуточное `viewportChanged(isStateStable=false)` не сдвигает нижнюю границу. Текущая высота отдельно доступна как CSS-переменная. Экран остаётся прокручиваемым.

При размонтировании отписываются те же функции и восстанавливаются прежние inline CSS/атрибут темы. Повторная очистка безопасна; даже если native offEvent бросает исключение, оставшиеся callbacks больше не изменяют документ. Optional presentation APIs не блокируют подписанный вход и серверную проверку допуска.

Если SDK появляется после браузерного восстановления уже подтверждённой сессии, он подключает native presentation API без повторного переключения в экран проверки доступа. Открытая деталь и черновик сохраняются; native closing confirmation получает текущее состояние несохранённого текста. При неподтверждённом доступе сохраняется прежний путь проверки сессии/Telegram-входа.

## Назад

`TelegramBackProvider` находится внутри подтверждённой сессии. Он регистрирует один native callback и показывает BackButton только при доступном внутреннем переходе. Общий hook хранит актуальный callback без повторных native подписок. Порядок: деталь/форма (30), развёрнутая панель (20), другой рабочий раздел (10); будущие модальные окна должны регистрировать приоритет 40.

- В задаче закрывается деталь; в проверке — форма решения с обновлением очереди.
- В управлении сначала закрывается форма редактирования/отмены, остаётся список управления.
- В исправлениях сначала закрывается форма с обновлением списка, затем панель исправлений, затем раздел баланса.
- После закрытия вложенного экрана следующий Back возвращает к исходному рабочему разделу: очередь проверки для проверяющего, свои задачи для остальных. В исходном разделе BackButton скрыт.

Все переходы проходят существующий `confirmLeave`; отклонение сохраняет текст, раздел и native кнопку. На отзыве доступа провайдер размонтируется, callback удаляется, кнопка скрывается. Сохранившийся после native ошибки старый callback не действует. Видимые кнопки закрытия и разделов остаются fallback для клиентов без BackButton.

## Проверка

`bun run check` проверяет формат, lint, типы, unit/contract-тесты и production build. `bun run test:telegram` после сборки и установки Chromium поднимает локальный Next production-сервер на 127.0.0.1:3101, запускает сценарии SDK/HTTP-симуляции и останавливает сервер. БД этой команде не нужна. Шаг добавлен в CI после установки Chromium; выполнение удалённого CI для этого изменения ещё не подтверждено.

Unit-тесты проверяют повторное подключение/отключение, восстановление документа, невалидные данные и ошибки native API. Browser-тесты проверяют размеры 320/360/390/1280, тему, viewport, отступы, поздний SDK, старые клиенты, приоритет вложенных экранов, отказ от потери текста и отзыв доступа. Состояния серверных 409/503 и повтор мутаций проверяются существующими сценариями форм; новых предметных операций этот срез не добавляет.

Первичный источник API: [Telegram Mini Apps — WebApp, события, BackButton, SafeAreaInset и ContentSafeAreaInset](https://core.telegram.org/bots/webapps), прочитан 02.10.2026. Новых зависимостей, миграций, внешних записей или выпуска нет. Точные результаты и ограничения — в [отчёте проверки](../verification/2026-10-02-telegram-bridge.md).
