# F06: явный срок и ручное истечение синтетического резерва

Основание: IMPLEMENTATION_PLAN.md §§ 5–7, F06 § 11, § 12. Это локальный технический срез, не утверждение P-03/P-04.

Версия косметики получает nullable `reservation_seconds`: положительное целое число секунд, явно заданное администратором тестовой БД. NULL означает отсутствие заданного срока; миграция не назначает сроки существующим версиям или заявкам. Новая заявка сохраняет `expires_at = created_at + reservation_seconds`; срок не ограничивается периодом квоты и не пересчитывается при смене условий. API каталога передаёт `reservationSeconds`, заявки — `expiresAt`. UI показывает длительность до подтверждения и сохранённый срок по Москве в истории и очереди.

`POST /api/v1/redemptions/:id/decide` расширяется решением `expire`. Существующее точное `reward.decide`, актуальная сессия, запрет собственного решения, причина, expectedVersion, CSRF, лимит и Idempotency-Key обязательны. После quota → balance → redemption locks сервер проверяет свой clock_timestamp: истечение возможно только для pending с заданным и достигнутым сроком; преждевременное истечение и одобрение после срока дают 409. Отказ и добровольная отмена остаются возможны; это другие сохранённые основания возврата. Approved/fulfilled не истекают.

Истечение переводит pending → expired, сохраняет автора/причину/время решения, возвращает исходную цену и место исходной квоты ровно один раз, не меняет XP/used. Журнал `reward_expiration`, audit `reward.expire`, outbox `reward.expired` и идемпотентный ответ записываются атомарно. Миграция расширяет ограничения и уникальность разрешения резерва; прямое просроченное одобрение или досрочное истечение запрещены БД. Аудит имеет отдельный allowlist полей.

Очередь остаётся существующим экраном; expire доступен только заявке с явным сроком. UI объясняет, что возврат требует серверной операции, и не объявляет его произошедшим по клиентским часам. Неопределённый итог сохраняет неизменное намерение для ручного replay. Чтения не меняют данные.

Проверки: миграция без backfill сроков/полномочий, NULL и snapshot, преждевременное истечение, просроченное одобрение, повтор и изменённое тело, терминальные переходы, отзыв доступа, гонки expire/cancel/reject/approve, откат при сбое outbox, независимая сверка 120→90+30→120+0 и квоты. HTTP и браузер на 320/360/390 px, клавиатура/reduced motion, регрессии F06.

Применять 000020 перед совместным выпуском API/UI. Для отката выключить SYNTHETIC_REWARDS_ENABLED; историю и миграцию не удалять. Автоматический scheduler/worker, администрирование каталога, реальная политика сроков, устройства, внешний выпуск и P-01…P-06 остаются отдельными задачами. Без ручного действия резерв остаётся pending и удерживает баллы/место; это ограничение среза явно сообщается в UI.
