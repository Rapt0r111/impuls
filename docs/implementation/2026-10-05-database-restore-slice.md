# R1: локальная проверка восстановления PostgreSQL

Основание: IMPLEMENTATION_PLAN.md §§ 8, 10, 12; серверные инварианты F01–F08. Это проверка синтетического восстановления, не согласование P-02/P-06, RPO/RTO или внешнего контура.

## Контракт до реализации

- Новый `bun run test:restore` требует явно заданного loopback `TEST_DATABASE_URL`, мигрированной тестовой БД и существующих ограниченных ролей `impuls_app`/`impuls_worker`. Не читает `.env.local`, production URL или секреты приложения. `PG_BIN` задаёт каталог существующих `pg_dump`/`pg_restore`; без него используется PATH. Несовместимость утилит с сервером — ошибка, не пропуск.
- Две пустые disposable БД создаются с непредсказуемыми именами `impuls_restore_<32 hex>_source|target`; удаляются только созданные текущим запуском имена. Исходная TEST_DATABASE_URL используется для подключения администратора, проверки ролей и CREATE/DROP собственных БД; её прикладные таблицы не читаются и не меняются.
- Source получает все реальные миграции через node-pg-migrate, включая журнал миграций. Поскольку роли общие для кластера, временная копия 000003 исключает только повторный CREATE ROLE impuls_app. SQL схемы и ACL сохраняется; 000021 использует штатную проверку существующей роли. Репозиторные миграции не меняются, роли не создаются/не меняются.
- Синтетический fixture: активные пользователи/сессии, точное полномочие, правила, принятая задача (17 XP/90 баллов), резерв косметики (30 баллов, одно место), связанные ledger/audit/outbox/achievement/history/idempotency records, завершённая симуляция и незавершённый lease с append-only журналом.
- `pg_dump --format=custom` копирует все схемы новой source, включая private таблицы и impuls_meta. `pg_restore --single-transaction --exit-on-error` восстанавливает только в пустую target, сохраняя владельцев и ACL. После ADR-0019 `--no-owner` запрещён: узкая SECURITY DEFINER операция требует восстановления своего NOLOGIN executor. Нужные глобальные роли уже существуют в том же тестовом кластере; новая процедура не переносит роли или секреты в другой кластер. URL/пароль не передаются в аргументах процесса, raw stderr утилит не печатается. Файл архива и временные копии миграций удаляются после проверки, включая сбой.
- До доменных операций target сравниваются все строки всех прикладных и migration таблиц, последовательности, определения таблиц/колонок/constraints/indexes/functions/triggers/policies и ACL. Независимые ожидаемые totals: XP=17, available=60, reserved=30; quota capacity=1/reserved=1/used=0.
- Повтор прежней приёмки и резервирования возвращает сохранённый ответ без новых строк/сумм; смена тела конфликтует. Последнее место остаётся занятым. После восстановления запреты UPDATE/DELETE immutable ledger/journal и ограничения worker остаются действующими. Отзыв активного пользователя отзывает восстановленную сессию и запрещает повтор.
- Завершённая симуляция не запускается повторно; действующий lease не захватывается до срока. После искусственного истечения восстановленного lease новый claim получает другой token/attempt, старый token отклоняется; trigger продолжает записывать журнал атомарно. Bot API отсутствует, outbox не считается отправленным.
- Проверка входит отдельным шагом Linux CI PostgreSQL 17.6; результат удалённого CI не объявляется проверенным по локальному прогону. Новых API/UI/зависимостей/миграций нет; ADR не требуется, архитектура сохраняется.

## Граница результата

Обе БД находятся в одном тестовом кластере. Глобальные роли, login/password/CA, Supabase Auth/Storage, внешние подключения и secrets не переносятся. Ежедневное расписание, хранение/шифрование копий, PITR, RPO/RTO, процедура восстановления на новом Supabase-проекте и ответственный оператор требуют отдельного эксплуатационного решения. Локальное время прогона не является производственным RTO. P-01…P-06, устройства и полная приёмка R1 остаются открытыми.

Первичные источники: [PostgreSQL pg_dump](https://www.postgresql.org/docs/17/app-pgdump.html), [pg_restore](https://www.postgresql.org/docs/17/app-pgrestore.html), [Supabase backups](https://supabase.com/docs/guides/platform/backups).
