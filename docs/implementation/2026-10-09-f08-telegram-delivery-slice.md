# F08: доставка нейтральных уведомлений через Telegram Bot API

Основание: IMPLEMENTATION_PLAN.md § 8 (outbox-worker, нейтральный текст, повторы с backoff и лимитом, сбой не откатывает решение), § 11 строка F08 («Сбой/повтор Bot API без двойных начислений»), § 12 (обязательный сценарий «ошибка Bot API»); ADR-0012, ADR-0025.

## Контракт

- Режим включается двумя независимыми флагами в окружении worker: `SYNTHETIC_NOTIFICATIONS_ENABLED=true` и `TELEGRAM_DELIVERY_ENABLED=true`, плюс `TELEGRAM_BOT_TOKEN`. Любой неверный токен или нелокальный `TELEGRAM_API_BASE_URL` — отказ запуска (`WORKER_UNAVAILABLE`, exit 1). Без второго флага worker только симулирует и не читает токен.
- Адресат — `users.telegram_id` активного получателя, доступный worker только через `impuls.lock_notification_recipient_chat(uuid)` (миграция 000032). Права на таблицу `users` у worker нет.
- Запрос: `sendMessage`, тело `{chat_id, text}`; текст — фиксированная строка по виду события (`neutralNotification`), без названий, отчётов, оснований и имён.
- Исходы:

| Ответ Bot API                              | Результат в очереди                                        | Журнал попыток     | Повтор                                                      |
| ------------------------------------------ | ---------------------------------------------------------- | ------------------ | ----------------------------------------------------------- |
| 200, `ok:true`                             | `delivered`                                                | `delivered`        | нет                                                         |
| 429                                        | `retry` или `failed` на пятой попытке, `rate_limited`      | `retry` / `failed` | не раньше `max(30·2^(n−1) с, retry_after)`, не более 3600 с |
| 403; 400 «chat not found»                  | `suppressed`, `recipient_unreachable`                      | `suppressed`       | нет                                                         |
| прочие 4xx/5xx, сеть, не-JSON, таймаут 5 с | `retry`/`failed`, `transport_unavailable` или `timeout`    | `retry` / `failed` | 30/60/120/240 с, пять попыток                               |
| 401, 404                                   | попытка остаётся `processing`, worker завершается          | только `started`   | после устранения причины и конца lease                      |
| получатель неактивен                       | `suppressed`, `recipient_inactive`, запрос не отправляется | `suppressed`       | нет                                                         |

- Событие outbox, баланс, журнал начислений, квоты и состояния задач/заявок не изменяются ни одним исходом.
- Приложение: сводка и списки событий/попыток F08/F07 показывают «Доставлено в Telegram», «Telegram ограничил частоту отправки», «Telegram не принимает сообщения получателя»; контракты принимают только эти новые значения. Поле `mode: "simulation"` не менялось.

## Границы

- At-least-once: возможен повтор уже принятого сообщения при потере записи результата или таймауте после отправки (ADR-0025). Exactly-once не заявляется.
- Нет планировщика напоминаний о сроках, событий закрытия сезона (R2), кнопки открытия Mini App, проверки `allows_write_to_pm`, hosting worker, алертов.
- Реальный токен, физические устройства, лимиты Telegram и P-01…P-06 не проверялись. Статус F08/R1 этой записью не меняется.
