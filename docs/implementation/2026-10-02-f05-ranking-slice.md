# F05: чтение синтетического месячного рейтинга

Требования: IMPLEMENTATION_PLAN.md §§ 5–7, 10–12, F05. Это первый срез F05; уровни, уникальная выдача «Первый результат», закрытие сезона и опубликованные снимки сюда не входят. P-05 не согласовано.

GET `/api/v1/leaderboard`: optional scope UUID, season YYYY-MM, cursor, limit 1–50 (20 по умолчанию). Текущий месяц определяется сервером в Europe/Moscow. Неизвестные и повторные параметры — 400. Ответ включает доступные синтетические области, выбранную область, личные XP/место, положительные строки рейтинга, revision, nextCursor, updatedAt. Нет членства — пустые области/строки, null scope/self. Недоступная область — 404 без раскрытия. Выключенный SYNTHETIC_RANKING_ENABLED — 404; флаг по умолчанию false, независим от приёмки и компенсаций.

Техническая политика ожидания: только активное, действующее, не отозванное явно синтетическое task_scope_members предоставляет просмотр своей точной области. Права task.view/review/admin не заменяют членство. В тестовом составе используются только псевдонимы. Новые реальные сведения или разрешение их публикации не вводятся. До real-data пилота нужна отдельная политика P-05; граница зафиксирована ADR-0005.

Сумма неизменяемых ledger_entries только currency=xp, mode=synthetic, season_key=выбранный месяц, time_zone=Europe/Moscow и task.scope_id=выбранная область. Записи компенсаций учитываются со знаком в исходном месяце, а не по дате исправления. Другие валюты/области/зоны исключены. Активные участники с действующим синтетическим членством: положительный итог попадает в список; нулевые значения не раскрывают публичный список неуспешных участников, собственное значение — 0 и null rank. `rank() OVER(ORDER BY xp DESC)` даёт 1,2,2,4; UUID сортирует только показ строк с равными XP.

Все чтения одного ответа — repeatable-read read-only PostgreSQL-транзакция под impuls_app, с новой проверкой сессии/допуска. Список страниц ограничен. Хеш доступных положительных итогов, имён, области и сезона образует revision. Курсор привязан к этой ревизии/области/месяцу/последнему UUID. При изменении между страницами — 409 RANKING_CHANGED, UI сохраняет прежний список с явной подписью и предлагает начать заново. Курсор не является разрешением. Полная агрегация области соответствует целевому масштабу около 40 человек; измерение большей нагрузки остаётся открытым.

UI расширяет существующее рабочее пространство кнопкой «Рейтинг», сохраняет защиту несданного отчёта. Выбор области и календарного месяца, личный результат, компактные строки, обновление/пагинация. Loading, empty, disabled, 404, 409, сеть/503, stale и отзыв сессии. Неизвестное внешнее состояние не заменяется моками.

Схема и гранты не меняются, миграция не требуется. Нет новых зависимостей или внешнего выпуска. План проверки: независимые PostgreSQL суммы/места/изоляция/компенсация, HTTP контракт/no-store/сессия, реальный Chromium→API→PostgreSQL путь, состояния и 320/360/390/1280 px. Точные выполненные команды и ограничения — в отчёте проверки.
