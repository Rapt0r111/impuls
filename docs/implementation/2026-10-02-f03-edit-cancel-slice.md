# F03: редактирование черновика и отмена

Основание: IMPLEMENTATION_PLAN.md §§ 4–6, F02/F03 в § 11 и отрицательные/конкурентные проверки § 12. Только синтетический режим; P-01…P-06 не утверждаются.

- `task.edit` и `task.cancel` — независимые права на точную область, без наследования от create/assign/review/admin. Они открывают список управления, но не чужую историю (`task.view` остаётся отдельным).
- POST `/api/v1/tasks/:id/edit`: полная замена названия, критериев, категории, приоритета, срока и фондов только в `draft`. Область, правила и исполнитель не меняются. Обязательны `expectedVersion`, UUID Idempotency-Key и причина 1–2000 символов. После назначения условия заморожены; нужна новая задача. Это консервативная инженерная граница текущего среза, не утверждённая служебная политика.
- POST `/api/v1/tasks/:id/cancel`: `draft/assigned/in_progress/in_review/needs_work → cancelled`, с версией и причиной. Принятую или уже отменённую задачу новый запрос не меняет. Назначение, отчёты, решения и журнал сохраняются. Непроверенный отчёт исключается из очереди по статусу задачи, без фиктивного review.
- Обе операции требуют SYNTHETIC_TASK_MANAGEMENT_ENABLED=true и действующей synthetic-версии правил. Replay проверяет текущий доступ/сессию/флаг, затем возвращает прежний ответ. Иное тело того же ключа — 409; отказ не оставляет идемпотентную запись.
- Строка задачи блокируется; отмена конкурирует с началом/сдачей/проверкой по той же версии. Только победившая приёмка создаёт начисления. Отмена сама не создаёт компенсации или уведомления; доставка и политика уведомлений остаются F08.
- Миграция 000013 расширяет права/аудит/события и разрешает UPDATE только полей условий; PostgreSQL trigger запрещает изменение условий вне перехода draft → draft. Новые события сохраняют снимок условий и основание, старые снимки остаются неизвестными (`null`). Runtime не редактирует историю. Rollback схемы запрещён при новых событиях/правах/аудите.
- UI использует существующие формы и кнопки. До подтверждения показывает задачу, исполнителя, фонды, версию и основание. Неопределённый результат/429 сохраняет тело и ключ, блокирует изменения и допускает ручной повтор. Конфликт сохраняет поля и требует явного выбора актуальной версии. Навигация защищает черновик.

Приёмка среза: PostgreSQL под impuls_app (права, версии, replay/revoke, закрытые статусы, гонки, rollback и неизменяемость), HTTP (Origin/CSRF/валидация/лимит), browser → API → БД, состояния и 320/360/390 px. PostgreSQL 17 CI, внешний выпуск и Telegram Android/iOS требуют отдельной проверки.
