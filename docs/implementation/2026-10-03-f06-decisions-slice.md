# F06: решения по синтетическим заявкам

Опора: IMPLEMENTATION_PLAN.md §§ 5–7, 10–12, F06; продолжает ADR-0008.

Контракт до реализации: `GET /api/v1/redemptions/review?scope=UUID&cursor=timestamp|UUID&limit=1..50` возвращает только pending в точной области `reward.decide`, сохранённые условия, получателя и сумму резерва. Своя заявка исключена. Список живой, без snapshot-гарантии. `POST /api/v1/redemptions/:id/decide` принимает только decision=approve|reject, expectedVersion и обязательную reason. Origin, session, CSRF, общий PostgreSQL mutation limit и UUID Idempotency-Key обязательны. Все ответы private no-store. Флаг SYNTHETIC_REWARDS_ENABLED остаётся false по умолчанию.

Одобрение потребляет сохранённый резерв баллов, переводит quota reserved в used и не меняет available/XP. Отказ освобождает исходную квоту и возвращает исходную цену один раз. Участник после решения видит автора, время и причину; одобрение явно не считается выдачей. Состояния approved/rejected неизменяемы в этом срезе. Новая pending для ещё не выданной approved запрещена. Решение после смены цены/отключения позиции/конца периода относится к исходным условиям; истечение не имитируется. Отмена после решения запрещена.

Домен повторно проверяет точные полномочия и срок сессии после ожидания блокировок; отказ в доступе предшествует replay. Порядок quota → account получателя → redemption общий с отменой. Decision, ledger, balance, quota, audit, outbox и idempotency commit атомарны. PostgreSQL guard сохраняет исходные условия и запрещает самоодобрение, переписывание решения и неверное направление журнала.

UI расширяет существующую витрину отдельной раскрываемой очередью только для reward.decide: scope, получатель, исходные условия/период/версия, выбор решения, причина и подтверждение. Неопределённый итог сохраняет точные body/key для ручного replay; конфликт требует обновления и нового подтверждения; уход защищает черновик. Устаревшие данные помечены, новые операции закрыты до успешного чтения. Мобильные размеры 320/360/390, desktop 1280, keyboard/reduced motion и отрицательные HTTP/DB сценарии входят в проверку.

Выдача reward.fulfill, уникальная косметика/entitlements, автоматическое истечение, admin catalog и расширение audit reader остаются следующим срезом. Функция F06/R1 не объявляется завершённой, P-01…P-06 не согласованы. Никаких реальных данных или внешнего выпуска.

## Эксплуатационные последствия

000018 требует совместимых contracts/readers приложения до открытия флага: старые клиенты не знают approved/rejected и нулевое движение available при потреблении reserved. Откат не удаляет ledger или решения; закрытие SYNTHETIC_REWARDS_ENABLED запрещает и отмену/отказ, но не освобождает pending автоматически. Уполномоченный тестового контура сначала проверяет pending, сумму account reserved и quota reserved; управляет остатками только существующими доменными операциями после включения совместимого кода. Прямое исправление проекций не заменяет финансовое решение.

При 409 новая версия/состояние требуют нового намерения после проверки. При timeout/503 тот же key/body позволяют узнать сохранённый итог; случайная новая операция не считается восстановлением. При 429 сохраняются intent и Retry-After, автоматического повтора нет. При отзыве полномочия saved response закрыт до повторного входа и текущего допустимого права. Outbox сохраняет нейтральное reward.approved/reward.rejected событие, но worker его пока не доставляет; интерфейс — текущий источник подтверждения решения.
