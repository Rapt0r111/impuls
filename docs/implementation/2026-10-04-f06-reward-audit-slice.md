# F06/F07: чтение аудита синтетических заявок

Основание: IMPLEMENTATION_PLAN.md § 4, 6–7, F06/F07 § 11 и проверки § 12; следующий срез после локальной выдачи 03.10.2026. Это расширение существующего reader, не изменение архитектуры; новый ADR не требуется.

## Контракт до реализации

- Схема: используем существующие audit_events.redemption_id, redemptions и reward_versions миграций 000017–000019. Новых таблиц, полномочий, экономических правил или мутаций нет.
- GET /api/v1/admin/audit: существующий независимый SYNTHETIC_AUDIT_ENABLED (false по умолчанию), активная сессия и точное admin.audit. Добавляются reward.reserve/cancel/approve/reject/fulfill. Права reward.decide/fulfill/admin.catalog и членство не дают аудит; право в родительской области не наследуется. Флаг записи наград не скрывает уже сохранённую историю.
- Для задач task сохраняется, reward=null. Для заявок task=null, reward содержит ID заявки/позиции/версии/квоты, неизменяемые title/conditions/price/rewardVersion/periodStart/periodEnd и получателя с текущим псевдонимом. Название берётся из снимка заявки, а не текущего каталога. Прежний статус события не заменяется текущим статусом заявки. Только явно синтетическая косметика в точной области.
- Только известные скалярные поля diff пересекают API; reward allowlist отдельный от task. Цена/версии положительны, availableDelta/reservedDelta знаковые; ID квоты/владения валидные UUID. Неизвестные ключи, вложенные значения, секреты, дроби и некорректные типы не передаются. У выдачи не реконструируются финансовые движения, которых нет в событии.
- Общая пагинация task/reward по точному PostgreSQL (created_at,id); курсор по-прежнему связан с читателем/областью/фильтром и существующим видимым anchor. Новая операция не создаёт повтор старой записи.

## UI и состояния

Расширяется существующий экран Operate и native disclosure. В списке — действие, автор/время, сохранённая позиция/текущий получатель и основание. В disclosure — условия заявки, цена/период/версия и только сохранённые значения события с ID. Статусы на русском; версия записи различается для задачи и заявки. Текущие имена явно отделены от снимка. Navy/Manrope, плоские строки, прежние размеры и reduced motion сохраняются; зависимостей и новых экранов нет.

Loading/ready/empty/invalid cursor/offline/503/disabled/404/401/403 применяют существующее поведение. При recoverable failure сохранённые записи остаются с временем чтения; при потере доступа скрываются. Refresh сбрасывает страницы, фильтр сбрасывает курсор. Validation/success/409 не применяются: экран не изменяет данные.

## План проверки

Контракт: все пять действий, signed delta и запрет несовместимого task/reward контекста/сырых diff. PostgreSQL под impuls_app: реальные reserve/cancel/reject/approve/fulfill, сохранённые условия после новой версии каталога, точная область и права, прекращение доступа, смешанная пагинация с микросекундами/равными timestamp, изменённый cursor, защита секретов и отсутствие записей при чтении. HTTP no-store, фильтры/дубли/лишние keys, Chromium → реальный API → БД. Browser: клавиатура disclosure, 320/360/390/1280, длинные имена/условия, пять фильтров, mixed paging, recovery/hidden rows и крупный текст. Общие format/lint/typecheck/unit/build и регрессии затронутых сценариев.
