# F04: синтетический возврат ошибочного начисления

Основание: IMPLEMENTATION_PLAN.md §§ 4–6, F04 § 11, проверки § 12. Это следующий локальный вертикальный срез этапа 3; P-04 и прочие P-решения не утверждаются.

- Только полный однократный возврат двух начислений одной приёмки. Произвольные суммы, бонусы, расходование, пересмотр приёмки и реальная экономика вне этого среза. Это консервативный тестовый контракт, а не служебный порядок.
- GET `/api/v1/admin/ledger-corrections`: курсорный список приёмок с исходными XP/баллами, получателем, областью, сезоном, правилами, актуальным балансом и ранее сделанной компенсацией. Доступ только по независимому `ledger.correct` в точной области. Опциональный `reviewId` позволяет перечитать выбранное начисление после конфликта. Это право не открывает чужой полный журнал/отчёты.
- POST того же пути: `{reviewId, expectedVersion, reason}`; UUID Idempotency-Key, версия **баланса получателя**, причина 1–2000 символов. Доступ/активная сессия, отдельный серверный `SYNTHETIC_LEDGER_CORRECTIONS_ENABLED=true` (выключен по умолчанию) и синтетические исходные правила проверяются также перед replay. Самокорректировка и неактивный получатель запрещены.
- Миграция 000014 добавляет неизменяемую запись решения, связанный audit/outbox и две компенсирующие строки журнала, с уникальностью по исходной приёмке/строке. PostgreSQL проверяет точное отрицание исходной суммы и сохранение исходного сезона/версии правил/получателя. Старые начисления остаются неизменными. Down допускается лишь до появления компенсаций.
- Блокировка проекции баланса сериализует приёмку/компенсации разных задач и конкурирующих проверяющих. Нехватка доступных баллов или XP даёт 422 без частичных записей. Резерв не расходуется. После всех ожиданий повторно проверяются сроки доступа/сессии. Replay возвращает сохранённый результат; другое тело того же ключа — 409.
- Компенсация относится к исходному сезону и меняет lifetime XP, не создаёт XP текущего месяца. Пока нет опубликованных снимков сезонов, errata/кубки не реализованы; перед их введением F05/F12 должен учитывать компенсации и поздние исправления отдельно. Приёмка и статус задачи остаются историческими фактами.
- UI расширяет существующий рабочий экран: список → inline подтверждение получателя, исходных сумм, нового баланса, сезона и версии → причина и checkbox → отправка. Конфликт сохраняет текст и требует явного принятия новой версии. Неопределённый результат/429 замораживает тело и ключ для ручного повтора; навигация защищает черновик. Личный журнал показывает знаки, тип исправления, автора и связь с исходной записью.

Проверки: PostgreSQL под impuls_app (права, replay/revoke, точные суммы, отрицательный баланс, гонки, rollback, append-only, up/down/up), HTTP Origin/CSRF/строгая валидация/no-store/429, Chromium → API → PostgreSQL, состояния и 320/360/390 px. Внешний выпуск, PostgreSQL 17 CI и физический Telegram требуют отдельной проверки.
