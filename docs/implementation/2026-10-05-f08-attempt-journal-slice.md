# F08/F07: журнал новых попыток симуляции

Дата: 05.10.2026. Основание: IMPLEMENTATION_PLAN.md §§ 3–4, 8, 10–12, F08 (повторы и состояние события), F07 (точные права). Только локальные синтетические данные.

## Контракт до реализации

Миграция 000023 добавляет append-only notification_simulation_events. AFTER UPDATE private receipts атомарно сохраняет started при новом захвате, retry/simulated/failed/suppressed при завершении, lease_expired при обнаружении потерянного захвата. При восстановлении записываются lease_expired старой попытки и started следующей; при исчерпании пятого lease — lease_expired и failed. Время — момент записи перехода в БД, а не точный момент падения процесса или доставки. Откат транзакции откатывает запись. История до миграции не реконструируется, существующие receipts/attempts/leases не изменяются.

Запись: UUID, outbox UUID, номер попытки 1–5, фиксированная фаза, фиксированный nullable error code, recorded_at UTC. Нет recipient/source IDs, текстов, bot token, lease token, сырых ошибок или времени внешней доставки. Private SECURITY DEFINER trigger с фиксированным search_path и без PUBLIC EXECUTE пишет журнал; app/worker не имеют INSERT/UPDATE/DELETE/TRUNCATE. App получает только SELECT минимальных полей с RLS; не добавляются права или публичный Data API. Новое решение границы записи — ADR-0015.

GET /api/v1/admin/notifications/attempts: действующие actor/session, exact admin.notifications в обязательной scope UUID и прежний SYNTHETIC_NOTIFICATION_STATUS_ENABLED=true (default false). Strict query limit 1–50 (default 10), optional actor|scope|notification-attempts|journalId cursor. Один statement snapshot проверяет права, область сохранённого synthetic outbox источника, доступный anchor и страницу; порядок recorded_at DESC/id DESC в PostgreSQL, без округления cursor. Pending не требуется: сохранённая synthetic история не исчезает при изменении состояния outbox. Response: mode simulation, scope, updatedAt, items (id, eventId как служебная identity outbox, kind allowlist, attempt, phase, recordedAt, errorCode), nextCursor. Идентификаторы не дают полномочий и не являются ссылками на задачу/заявку. 400 invalid cursor/query, 401 expired/missing, 403 revoked/inactive, 404 disabled/hidden scope, 503 unavailable. POST 405; private/no-store.

Пользователь выбрал закрытое native disclosure «Журнал попыток» внутри существующей поверхности. Lazy query, собственные timestamp/refresh/next; обновление возвращает первую страницу. Тип события, номер попытки, текстовая фаза, время записи и причина; служебная identity для различения однотипных событий раскрывается отдельно. Пояснение границы истории/симуляции и обнаружения истечения lease. Loading/empty/error, retained dated rows при 503/offline, скрытая страница при 400. 401/403/404 отменяют параллельные queries и очищают все три protected caches; отказ сводки/списка также очищает журнал. Scope key/AbortSignal защищают от late response. Telegram Back закрывает раскрытие до выхода из раздела. Существующие сводка/recent20/список событий сохраняются.

## Проверка

Реальная PostgreSQL: миграция сохраняет старые receipts без backfill; least privilege и append-only; claim/result/retry/suppression/timeout, crash/reclaim и пятая потеря; rollback, stale token и гонки не создают ложные/повторные строки. Чтение под impuls_app: exact permission, session expiry/revocation/inactive, hidden scope, cursor forgery и полная пагинация с микросекундами/tie UUID. No mutation при чтении. HTTP strict query/no-store/405/minimal projection и browser-to-DB. Browser 320/360/390/1280, keyboard/Back, enlarged text/reduced motion, lazy/loading/empty/retained503/offline/400/denial/late response. Unit/typecheck/lint/format/build и независимый UI review.

За рамками: Bot API/неоднозначная внешняя отправка, supervisor/hosting, retention policy и реальная нагрузка, catalog writes, automatic expiry F06, remote rollout, устройства, P-01…P-06 и полная приёмка F08/F07/R1. После миграции API/UI выпускаются вместе; отдельный rollback удалением истории запрещён.
