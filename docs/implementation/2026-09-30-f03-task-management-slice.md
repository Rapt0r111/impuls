# F02/F03: создание и назначение задачи

Дата: 30.09.2026. Контракт среза перед реализацией. Основание — IMPLEMENTATION_PLAN.md §§ 4–7, F02/F03 § 11, § 12. Архитектура и зависимости сохраняются.

- POST `/api/v1/tasks` создаёт `draft` только с отдельным `task.create` в точной области. Клиент передаёт название (1–120), критерии (1–2000), технический код категории (1–40), приоритет, UTC-срок, UUID области/правил и целые тестовые фонды (0–2147483647). Категория не означает утверждённую номинацию.
- POST `/api/v1/tasks/:id/assign` принимает UUID исполнителя и expectedVersion; требует отдельное `task.assign` в области задачи и переводит только draft в assigned. Повторное назначение и изменение работающей задачи в этот срез не входят.
- В новой таблице `task_scope_members` фиксируется явное тестовое членство пользователя в области. Права проверяющего не означают членство исполнителя; права родительской области не наследуются. Записи пока создаются только администратором тестовой БД, интерфейс управления составом F07 отсутствует. Runtime не меняет состав.
- Создание/назначение выключены по умолчанию серверным `SYNTHETIC_TASK_MANAGEMENT_ENABLED`; разрешены только версии правил `mode=synthetic`, уже вступившие в силу. Это технический режим тестирования, не решение P-01/P-04. Список правил и исполнителей загружается с сервера.
- GET `/api/v1/task-management` возвращает задачи только областей с действующим create/assign; пагинация по UUID, лимит 1–50 (20 по умолчанию). GET `/api/v1/task-management/options` возвращает области и отдельные возможности create/assign, доступных тестовых исполнителей и синтетические версии правил. Список исполнителей доступен только при assign.
- Мутации проверяют Origin, CSRF, сессию, допуск, UUID Idempotency-Key. Транзакция сериализует назначение через родительскую задачу; до сохранённого ответа повтор проверяет текущие права. Проверки сроков повторяются после блокировок. Создание/назначение, idempotency, аудит и нейтральный assignment outbox атомарны; начислений нет.
- Аудит/outbox расширяются nullable task_id с ограничением ровно одного объекта (review либо task); существующая история review сохраняется. Новый outbox не доказывает доставку.
- UI: создание черновика, список, отдельное подтверждение назначения с исполнителем/критериями/фондами; загрузка, пустота, ошибка, конфликт, недоступные правила/исполнитель, отзыв. Неопределённый ответ сохраняет точные тело и ключ для повтора; формы защищены от потери текста.

Проверка: контракты; PostgreSQL под impuls_app с отрицательными правами/членством, повтором и гонкой назначения, откатом аудита, независимыми DB-инвариантами; реальные HTTP/браузерные сценарии, 320/360/390 px и клавиатура. P-01…P-06, Telegram Android/iOS, выпуск схемы/кода и завершение F02/F03 остаются отдельными условиями.
