# F08: жизненный цикл постоянного worker симуляции

Основание: § 8, F08 § 11, режим ожидания § 10 и критерии § 12 `IMPLEMENTATION_PLAN.md`; [ADR-0013](../adr/0013-synthetic-worker-watch.md). Это локальное продолжение [первого worker](2026-10-04-f08-simulation-worker-slice.md).

## Контракт

- Схема и гранты не меняются: 000001–000021, отдельный impuls_worker, private notification_simulations. Исходный outbox остаётся pending после успешной симуляции, финансы/заявки/audit не меняются.
- CLI принимает ровно один аргумент `--once`, `--status` или `--watch`. Старые команды сохраняют поведение. При false flag любой корректный режим возвращает disabled/exit 0 без проверки URL/паузы и без подключения.
- При true `--watch` проверяет poll interval до подключения: цифры, целое 1000–60000 мс, default 5000. Пустое значение, дроби, экспоненциальная запись, NaN, пробелы и выход за пределы дают нейтральный WORKER_UNAVAILABLE/exit 1.
- `--watch`: watching после проверки роли, до 20 последовательных claim/process за пакет, пауза после каждого пакета. Новый outbox подбирается следующим пакетом; retry сохраняет прежний next_attempt_at/backoff, чужие действующие leases не захватываются. Idle не порождает логи; непустой пакет пишет только счётчики пяти результатов.
- SIGINT/SIGTERM: пауза прерывается, новые claim прекращаются, начатый claim/process завершается, затем пул закрывается. Контроль stop не заменяет проверку active/lease внутри домена. Повторный сигнал не продлевает 20-секундный deadline. Graceful signal exit 0; ошибка соединения/таймаут stop — exit 1 с фиксированным кодом. Deadline защищает также закрытие пула.
- Настройка flag читается при запуске. Оператор выключает работающий процесс сигналом; для последующего запуска задаёт false. Sink остаётся локальным без Bot API; любые квитанции означают только симуляцию.
- Ошибка БД не порождает внутренний reconnect. Перезапуск с задержкой — будущая настройка внешнего supervisor. Kill/crash оставляет исходный lease; до срока новый запуск его не забирает, после срока получает новый token и следующую попытку.

## Запуск и остановка

```powershell
bun run build:worker
# Только отдельная синтетическая БД/роль worker; flag=true задаётся явно в окружении worker.
bun run worker:watch
# Ctrl+C в интерактивном терминале завершает обработку текущего события.
```

Для supervisor/container используйте непосредственный Node entry point из корня репозитория:

```text
node apps/worker/dist/index.mjs --watch
```

Не запускайте миграции/создание полномочий вместе с worker. Grace period хоста должен быть больше 20 секунд; до kill дождитесь завершения процесса. Рестарты должны иметь задержку, а не создавать поток подключений при недоступной БД. Хост, CA, runtime login, политика рестарта и мониторинг требуют отдельной эксплуатационной настройки. Реальный контур не выпускается этим срезом.

```powershell
$env:TEST_DATABASE_URL='postgres://impuls_test@127.0.0.1:55432/impuls_f03'
bun run test:notifications
```

Тесты создают проверенную по имени disposable `impuls_notifications_<uuid>`, применяют 000001–000021 и удаляют только её. Новые тесты процесса также запускают реальный собранный Node child; управляемое завершение транзакции проверяется через AbortSignal с PostgreSQL. POSIX SIGTERM тест явно skipped на Windows и должен исполняться в Linux CI. Принудительный kill на Windows проверяет crash recovery, а не graceful signal.

## Граница результата

Новые API/UI отсутствуют, поэтому Telegram размеры/клавиатура/reduced motion не относятся к этому изменению. Супервизор, hosting, проверка 20-секундного hard stop на целевом хосте, PostgreSQL 17.6 CI, Bot API/consent/неоднозначный исход отправки, admin delivery UI, reminders/season events, нагрузка, backup restore и P-01…P-06 остаются открытыми. F08/R1 не объявляются завершёнными. [Свидетельства](../verification/2026-10-04-f08-watch.md).
