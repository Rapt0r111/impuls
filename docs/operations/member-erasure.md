# Удаление данных выбывших участников (P-02)

Решение владельца P-02 от 10.10.2026: Telegram ID и имя выбывшего участника удаляются через 90 дней после выбытия. Правило и работа — в базе ([ADR-0033](../adr/0033-departed-member-erasure.md), миграция `000041`); скрипт [`scripts/erase-departed-members.mjs`](../../scripts/erase-departed-members.mjs) только вызывает функцию под ролью миграций.

## Когда запускать

Раз в неделю, пока нет размещённого планировщика. Первые удаления возможны не раньше чем через 90 дней после первого выбытия. Пропуск недели переносит удаление, но не теряет его: функция берёт всех, у кого срок уже прошёл.

## Запуск

```bash
MIGRATION_DATABASE_URL=postgres://… node scripts/erase-departed-members.mjs
```

Сухой прогон (по умолчанию) ничего не записывает и печатает: `due` — сколько учётных записей уже пора удалить, `erased` — кого удалит запуск с `--apply`, `waiting` — сколько выбывших ещё не дошли до срока, `nextDueAt` — когда наступит ближайший срок.

Если список верный, тот же вызов с `--apply`. `--limit N` (1–1000, по умолчанию 100) ограничивает число записей за запуск. Нужно прямое подключение к PostgreSQL владельцем схемы; адрес `*.pooler.supabase.com` скрипт отклоняет.

## Что меняется

У каждой удалённой записи: Telegram ID стёрт, имя заменено на «Удалённый участник», удалены сессии, история имён и сохранённые ответы с её UUID. Журнал, балансы, рейтинг, решения и аудит остаются и ссылаются на ту же учётную запись. След — строка в `impuls.member_erasures` без персональных данных.

Если человек вернётся, его допускают заново через «Состав»: создаётся новая учётная запись, прошлые начисления к ней не переходят.

## Проверка после запуска

```sql
SELECT count(*) FROM impuls.users WHERE erased_at IS NOT NULL;
SELECT user_id, departed_at, erased_at FROM impuls.member_erasures ORDER BY erased_at DESC LIMIT 10;
```

## Ограничения

- Резервные копии хранят прежние данные до истечения их срока хранения.
- Свободный текст задач и отчётов не проверяется (по P-02 сведений о людях в нём нет).
- Запуск на Supabase/Production этой процедурой ещё не выполнялся.
